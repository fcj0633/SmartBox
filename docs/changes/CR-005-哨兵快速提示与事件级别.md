# CR-005 哨兵快速提示与事件级别

状态：用户已确认。日期：2026-11-17。来源：用户批准 TASK-008 实施计划时对哨兵输出和事件级别映射的选择。本文只补齐 TASK-008 原标记为待确认的规则，不改变冻结契约、Topic、数据字段、既有需求编号或历史记录。

## 原因与范围

TASK-008 已要求布防异常后 1 秒内本地提示，并要求契约事件带级别，但此前没有确定各角色实际使用的提示输出组合/持续时间，也只有哨兵侵入的级别确定。实现前需固定这些可验收规则，避免固件、模拟器和后端采用不同解释。

## 已批准规则

1. 哨兵快速异常本地提示只使用灯光：ENV 使用 IA1 补光灯，POSE 使用 SC2 指示灯；不启动风扇。有效快速异常触发后，灯光持续 10 秒并自动关闭。仍须满足原有 1 秒内开始提示要求。用户确认的“灯光”映射到各节点已有受控灯输出，不新增硬件输出类型。
2. 事件级别采用以下映射：

   | 事件 | 级别 |
   |---|---|
   | `SENTRY_INTRUSION` | `CRITICAL` |
   | `ENV_HIGH`、`ENV_LOW`、`IMPACT`、`GEOFENCE_EXIT` | `WARNING` |
   | `ENV_RECOVERED`、`POSE_CHANGED`、`DOOR_EVIDENCE`、`GEOFENCE_ENTER` | `INFO` |

3. `DEVICE_FAULT`、`STORAGE_OVERFLOW` 等不属于上述规则事件的级别仍由产生者按其已定义的严重度及实际故障语义处理；本 CR 不为其新定映射。

## 兼容与未决项

- 级别值均使用现行契约允许的枚举，不增加字段或消息类型。
- 哨兵侵入告警何时自动恢复、人工告警处置、围栏配置入口、门相反证据、`box_state` TTL、重启后哨兵期限恢复及未校时历史双源质量仍按 TASK-008 对应 Q 项保留，不由本 CR 推导。
- TASK-008 只生成易失事件候选；真实板事件持久化、发送与补传仍属于 TASK-009。
