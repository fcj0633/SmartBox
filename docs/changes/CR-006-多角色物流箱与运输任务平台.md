## 1. 变更背景与必要性

SmartBox 现有基线围绕已预配置的逻辑箱体（ENV/POSE 双节点）、采样、姿态/异常规则、MQTT 接入、远程控制、事件与告警、角色授权和按箱体查询构建。正式前端提供登录、箱体列表、详情和设备控制。

需求发生变化：项目不再仅提供**箱体监测视图**，还需要表达**谁拥有箱体、谁在当前期间使用箱体、此箱执行哪一次运输、物品与任务如何绑定、普通用户能查看哪次运输**。企业端需以地图/资产运营为主要信息架构，骑手以运输任务为操作中心，普通用户无需注册完整账号即可凭运输编号和验证码只读查看本人被授权的任务。

此项不是纯 UI 变更。没有企业关系、分配、运输任务、任务级历史及访客授权的数据模型，三个前端无法正确、安全地共同使用同一套监测数据。现有 `box_id + received_at` 查询不能直接保证相邻运输任务之间的数据隔离，尤其需要处理设备时间不可信及断网迟到/补传。

## 3. V1 工作默认规则与用户决策边界

> 用户已明确要求在不确定处使用默认实现。本节对 V1.1 第 15 章 的 MR-Q-01～17 作 CR 级摘要。这里的**默认实施口径**用于后续产品/技术评审和开发方案，不将“用户要求写文档”冒充 17 项逐条生产审批；有冲突时先提交后续 CR，不得在编码过程中私自选择另一方案。

| MR-Q | V1 采用的默认规则 | 后续扩展/限制 |
|---|---|---|
| Q-01 身份 | 账号可有个人资产和企业关系；每次请求只有一个明确的活动业务上下文，旧角色不得自动拥有企业管理员身份 | 多企业并行/复杂组织后置 |
| Q-02 权属 | 箱体由受控初始化或有资格的管理员登记企业/个人所有权；分配使用不转移权属 | 不开放输入箱号自行抢绑或过户 |
| Q-03 创建任务 | 获准骑手对有权使用的箱体创建准备任务，服务端生成唯一运输编号；企业可查看授权范围 | 企业派单/外部订单后置 |
| Q-04 物品 | 一任务关联一份物品摘要：名称必填（默认上限 50 字），简述可选（默认上限 200 字），可代表一件或一组物品 | 不做逐件商品清单或联系方式 |
| Q-05 箱任务关系 | 一任务固定一个箱体；READY 不永久占箱；同箱最多一项 ACTIVE，运输中不换箱 | 多箱联运与途中换箱后置 |
| Q-06 开始/结束 | 开始与结束都需后端可达；设备离线禁止新开始；在线但数据异常/过期需显式风险确认与审计；合法操作者可在设备离线时结束 | 结束不等于签收/警报恢复/补传完成 |
| Q-07 撤权接管 | ACTIVE 时普通撤回分配应拒绝；紧急撤权立即阻断旧骑手，具明确资格的企业人员审计接管并结束任务 | 不自动结束任务 |
| Q-08 历史 | 企业/骑手按当时参与事实与明确历史权限查询，当前授权撤销不删除历史，也不无限继承他人历史 | 严格隐私字段裁剪 |
| Q-09 凭据 | 服务端用安全随机源生成单任务 10 位字母数字验证码，只保存安全散列；骑手/获准运输方安全提供给用户。运输中及结束后 7 天有效；访客只读会话 30 分钟；默认 15 分钟内 5 次失败触发限制，并补 IP 维度限流；重签/撤销令旧会话失效 | 数值可配置，需安全评审；不在 URL/日志暴露原文 |
| Q-10 时间归属 | 服务端记录可信的 UTC 任务边界，查询用 `[start_at,end_at)`；只有通过质量检查的可信发生时间才可用于任务归属，接收时间不得直接替代。补传尽可能归还原任务，未知单列待核且不得展示为访客历史 | TASK-009 真实补传完成前，历史完整性不可承诺 |
| Q-11 设备权限 | 个人拥有/企业分配均保留现行 COURIER 的受限动作，不能由所有权直接获得画像、校准、GPS 模式、灯风扇或导出权限 | 高级权限需单独审批 |
| Q-12 多人/多任务 | 同一企业箱体同时最多一条有效骑手分配；单骑手可管理多个箱体及分别进行中的任务；单箱仍只能一项 ACTIVE | 多骑手协作后置 |
| Q-13 状态 | READY→ACTIVE→COMPLETED；准备阶段可调整摘要或丢弃未开始草稿；进行中不取消、不换箱、不解绑；结束后只能建立新任务 | 取消/重新打开后置 |
| Q-14 留存 | 初步目标为遥测 90 天、事件/告警 180 天、任务与审计 365 天；上线清理策略需另经数据安全/运维验证 | 本 CR **不启动任何清理**，不能误删现存数据 |
| Q-15 地图 | 企业地图为入口，演示位置必须显示 MOCK；缺坐标走列表，底图失败仍可查看箱体 | 真实 GPS/地图供应商另立方案 |
| Q-16 人工告警 | V1 提供告警及恢复的只读状态，不提供可执行的人工确认、关闭、派单按钮 | 人工处置另立 P1 需求 |
| Q-17 隐私 | 仅收集最低物品摘要；企业/骑手/访客分别按资源与任务范围提供白名单，不向访客暴露原始节点证据、其他任务和设备凭据 | 电话、地址、支付、客户身份数据不纳入 V1 |

### 3.1 规则生效与冲突处理

- “V1 默认”表示**拟采用的开发规则**，并非现行 API 已支持；新功能正式对外启用前，要将本节对应 MR 条目转为正式 REQ、接口契约、数据约束和测试用例。
- 涉及现行 MOD-05 明示排除的运输生命周期、MOD-06 已有角色/账号约束，以及总纲 Q-13 的部分内容，**必须通过需求基线变更明确覆盖范围**，不能仅靠本 CR 的文字直接在生产中放开权限。
- 原 Q-01～14 与多角色 MR-Q-01～17 分别追踪；本 CR 不自动关闭尚未解决的真实哨兵恢复、时间、围栏配置及 Flash 可靠性问题。
- 涉及安全/个人信息的默认参数可作为评审起点，但上线前必须经过针对访问凭据、会话吊销和日志脱敏的专项验证。

## 4. 三端功能及页面落地边界

### 4.1 企业端（桌面优先）

主要入口为**物流地图运营控制台**：企业授权资产地图与列表联动、在线/异常/运输筛选、箱体详情、运输任务、告警中心、设备管理和企业箱体分配。地图数据必须可证明来源；现在没有真实 GPS 的资产不得画出虚构当前位置。清单/明细是底图故障和无坐标时的保底入口。

P0 交付允许明确标注 MOCK 的地理展示，但**不得宣称真实车队位置、路线、预计送达或自动调度**。企业成员管理仅实现满足箱体分配所需的最小动作授权；复杂组织及人工作业告警后置。

### 4.2 骑手/个人箱主端（移动优先）

默认首页为当前运输工作台。当前有任务时突出物品、箱体、环境判断、数据时间和“查看当前运输”；无任务时突出“开始新运输”。保留“我的箱体”“运输记录”“我的”入口。

三步主流程：**选择有资格的可用箱体 → 绑定一份物品摘要 → 确认并开始**。实际后端创建任务与服务端事务保证排他；任务详情允许经授权结束并保留历史。自有箱体与企业分配箱体要明显区分来源，但不借来源升级设备控制权限。

### 4.3 普通运输用户端（移动优先）

运输编号＋验证码验证后直接进入**单次运输概览**：物品摘要、任务阶段、统一环境结论、关键读数、数据时间、运输进度、历史环境及异常。只能访问这一任务；过期、撤销、退出后不得从旧页面或 WS/HTTP 继续获取数据。

不提供资产目录、跨箱查询、节点诊断、设备控制、任务结束、企业管理或箱体级 CSV 导出。已结束任务展示历史，不用同箱下一任务的最新快照覆盖旧任务。

### 4.4 交互与状态共用约束

所有入口必须区分设备在线、采样有效、数据新鲜、环境/告警已评估和任务状态；UNKNOWN 不显示为正常。Loading/Empty/Error/Offline/Stale/Invalid、授权失效、部分节点不可用均需有可解释页面状态。三端使用同一后端业务结论，不能各自在前端重新计算环境阈值。骑手与访客以手机优先，企业以桌面优先，并在 390×844、768×1024、1440×900 验收。

现有三个 UI 方向的代码属于独立 Mock 演示；**不得因原型按钮可点击而标记真实业务接口已交付**。

## 5. 跨端业务与安全验收门槛

### 5.1 最小业务流程

1. 受控登记箱体企业/个人权属；企业经独立管理权限将企业箱体分配给骑手。所有权与使用资格分离。
2. 骑手登录后仅查可使用箱体，选箱创建服务端 READY 任务并绑定物品摘要。READY 不意味着已有有效运输过程数据。
3. 开始时后端重新验证骑手、箱体、物品和排他约束，在单次事务中记录 ACTIVE 和可信开始边界。并发/重复操作不得造成双占用。
4. 原有 ENV/POSE 采样、统一规则、EMQX、后端业务视图持续运行，任务查询通过服务端关联合法采样与事件；数据无可信时间时不得猜测归属。
5. 获准运输方安全交付任务编号和验证码，普通用户获取受限短期只读会话，查看该次运输的授权字段/时间段。
6. 骑手经授权结束任务，后端原子记录 COMPLETED、结束时间和箱体占用释放；后续新运输使用新身份。已完成记录不因新任务改变。
7. 跨角色访问、撤权、旧会话、历史时间区间扩大及 WS 订阅均由**服务端**强制授权和审计。

### 5.2 必须可验证的典型验收

| 场景组 | 关键断言 | 来源 |
|---|---|---|
| 所有权/分配与企业隔离 | 企业 A/B 无交叉资产，骑手只见自有及有效分配，收回不转移权属 | MR-A01/02/14/17 |
| 创建/绑定/开始/结束 | 无权绑定拒绝；未绑定无法开始；同箱并发至多一个 ACTIVE；重复结束不改原结束时间；新任务不覆盖旧记录 | MR-A03/04/05/16/18/19 |
| 紧急撤权 | 旧骑手已打开页面也不能继续受保护操作；明确授权企业接管者可审计结束；不自动伪造完成 | MR-A02/20 |
| 访客凭据 | 错误、过期、重签、撤销及失败频率均无法泄露任务存在性；旧会话/推送失效 | MR-A07/12/21 |

### 5.3 非功能与可靠性

- 继续适用已有 NFR-001～003、现行授权/审计与 CR-004 时间质量要求；不通过新 UI 添加未验证的性能 SLA。
- 开始/结束需设计事务一致性、并发排他及请求超时后的结果查询；不得用前端按钮禁用代替服务端幂等。
- 访客授权必须被 REST、WS、聚合、导出和所有关联查询共同执行；敏感凭据不进入 URL、日志、错误信息或前端永久存储。

## 7. 风险与降级策略

| 关键风险 | 可能后果 | 默认缓解及阻断条件 |

| 业务数据保留方案直接上线删除 | 意外丢失审计/历史 | 本 CR 不实施清理，另审留存、备份、迁移与恢复 |
| TASK-008 短测误当完整可靠性 | 云端断网、事件掉电场景误判通过 | 明确跳过的板端场景；TASK-009 作为可靠事件独立验收依赖 |
