# 路线图

| 阶段 | 交付 | 门槛 | 任务 |
|---|---|---|---|
| P0 | 文档、目录、Git、需求拆解、契约和首轮任务 | 文档一致、链接有效、原文保全 | TASK-000 |
| P1 | 双角色骨架、Spring Boot/MySQL、Vue、模拟节点实际 MQTT 闭环 | 消息真实入库、授权展示和命令回执可用；不依赖接板 | TASK-001～006 |
| P2 | 双板真实采集和输出接入 | 真实串口、固件版本、两节点数据与输出证据齐全 | TASK-007 |
| P3 | 规则、融合、哨兵、GPS Mock、角色界面 | 业务规则对应 TC 通过 | TASK-008 |
| P4 | 持久化、恢复、补传、资源验证 | 容量与溢出可区分，掉电/断网用例通过 | TASK-009 |
| P5 | 历史/轨迹/导出、部署与完整回归 | 所有必需需求验收、24h 实测与演示材料齐全 | TASK-010 |

P1 可并行推进固件骨架、后端及前端。契约是并行开发的共同依赖。P2 后调整硬件相关假设；不因等待实物暂停后端和前端工作。阶段不是固定日历周期。

## 六模块与交付切片

P1围绕[MOD-03](../requirements/modules/MOD-03-设备接入与控制.md)、[MOD-04](../requirements/modules/MOD-04-事件管理与可靠性.md)、[MOD-05](../requirements/modules/MOD-05-物流箱管理与状态聚合.md)、[MOD-06](../requirements/modules/MOD-06-用户与权限管理.md)的既有骨架和真实链路切片推进；MOD-01仅使用模拟输入，MOD-04本地持久化仍留后续。P2接真实采集，P3展开监测和哨兵业务，P4可靠性，P5完整交付。这里的模块关联不改变上表阶段、验收、依赖或人员安排，也不表示任一阶段验收整个模块。
