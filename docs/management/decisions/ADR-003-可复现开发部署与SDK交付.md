# ADR-003 可复现开发部署与 SDK 交付

| 属性 | 内容 |
|---|---|
| 状态 | 采用；实现和复验结果见部署报告 |
| 日期 | 2026-11-09 |
| 依据 | 用户明确要求完整开发代码、详细部署指导，并选定 Windows＋Ubuntu、独立完整 SDK 包和部署可复现性优先 |
| 影响 | 开发配置、首次项目库、服务进程、SDK 依赖交付、固件同步与部署文档 |

## 背景

已有代码能够在原开发机运行，但依赖既有秘密、项目库、磁盘映射和 SDK 工具目录。单纯列出启动命令不能指导第一次部署；仅提供上游可变分支也不能还原已验证 SDK。业务未完成项与安装缺口必须分别说明。

## 决定

1. 以[完整部署指南](../../delivery/deployment/开发者完整部署指南.md)为新开发者主入口，`tools/project.py` 组合既有工具，不建立另一套服务。
2. 首次配置随机生成项目凭据，初始化数据文件使用仓库相对引用。既有秘密和代次不重置；已有私有路径不自动猜测迁移。Windows 选择器兼容项只在确认需要时显式启用。
3. 首次建库独立显式执行；数据库与账号名称仍限定项目范围，应用不使用管理员。默认 3306，允许本机其他有效 TCP 端口供隔离实例使用。建库归属记录绑定服务端 UUID 和端口，DDL 失败不宣称整体回滚，不接管未知同名对象。
4. 固件新增 SSH-only 同步，复用原三方指纹、冲突检查和受控恢复；保留映射方式。Ubuntu 工具目录来自私有配置，只加入构建子进程 PATH，工作器兼容现有 Python 3.8。
5. SDK 和 GN/Ninja/RISC-V 工具链以独立压缩包、逐文件/权限/链接清单交付，保留许可证和分发调整。原 SDK 不修改；剔除个人实验、生成配置和旧输出，在新目录验证安装及双角色构建。
6. 当前 SDK 缺少上游提交元数据，明确标注派生本地快照，以树清单追溯，不虚构版本。完整本地交接不等于公开再分发授权已完成，厂商及编译器条款仍须核对。
7. 服务启动管理器只持有自己创建的进程，停止请求验证进程创建身份；冲突端口失败，不结束外来进程。数据库演练使用本轮私有数据目录和 13306 实例，不停止共享 MySQL。

## 不改变的边界

不新增业务 API，不调整报文、业务阈值或角色规则，不改 174 份冻结文件及已应用 V1～V9。真实固件仍只执行 output，GPS 为 MOCK；TASK-008～010 不自动完成。依赖安装仍以现有锁文件为准，交付不是整机离线镜像。

## 维护要求

配置生成、进程管理、压缩包安装等错误路径须有临时样例测试。交付源码必须从已提交的清洁 Git 树导出，记录提交号和 SHA256。凭据、账本、原始日志和大体积 SDK 包继续在忽略目录保存；受控报告保存脱敏结果和相对证据索引。
