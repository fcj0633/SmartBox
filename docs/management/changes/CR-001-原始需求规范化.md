# CR-001 原始需求规范化

日期：2026-11-06；状态：已批准（依据用户实施计划）；生效基线：BL-001。

| 原始设计 | 有效规范 | 影响 |
|---|---|---|
| 单份根需求，技术选型有多项候选 | 原文归档，多 REQ/NFR；固定 Spring Boot/MySQL/Vue | 文档体系、ADR-001 |
| M0 先完成硬件验证 | 硬件正常假设，P1 直接开发，P2 实测 | 路线图、TASK-002/007 |
| 实际箱体、声光、电机短振 | 动作模拟、灯和风扇；声音不验收 | REQ-003/004 |
| 64 条覆盖且单节点不丢 | 容量内保证，溢出累计计数且可见 | REQ-006 |
| 单节点 seq、部分报文缺 boot_id | node_id+boot_id+event_seq 标识事件 | MQTT、数据库唯一约束 |
| ack 同时承担多类确认 | command_ack 上行、event_ack 下行；落库成功才确认 | contracts、REQ-006/007 |
| ENV caps=7，不接收 sentry | ENV caps=71；POSE caps=120，均支持哨兵 | contracts、REQ-004 |
| 所有事件 ≤2s、本地 ≤1s、证据持续 1.5s | 本地快速异常与云端融合分开验收 | NFR-001 |
| 姿态与门安装关系不清 | 手动动作脚本，真实安装准确率另行验证 | REQ-002/003 |
| 外卖用户是否可看开门记录不一致 | 可看融合结论与相关告警，不能看原始证据 | REQ-009 |
| 可变 WebSocket token URL | 短时一次性 ticket，禁止长期 token 写 URL 日志 | HTTP 契约、NFR-003 |

原文 FR-01/02 → REQ-001；FR-03 → REQ-002；FR-04 → REQ-003；FR-05 → REQ-004；FR-06 → REQ-005；FR-07 → REQ-006。支撑能力拆为 REQ-007～009，质量约束拆为 NFR-001～003。

这些差异已落实在有效需求与契约，原始输入保留不变。后续不在此持续追加无关变更，新增 CR 编号。
