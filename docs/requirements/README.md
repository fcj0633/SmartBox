## 编号、状态与修改

REQ 业务需求；NFR 非功能需求；TASK 开发任务；TC 测试用例；ADR 技术决策；CR 基线变更。编号不随迭代重排，不复用取消编号。

需求状态：草案 → 已确认 → 开发中 → 待验收 → 已验收；终止时为已取消。实现状态在任务及追踪矩阵维护。“已确认”表示规则可据以开发，不代表已实现或实测通过。

新业务使用 [需求模板](../templates/需求模板.md) 建独立文档；一项需求可跨三端，由多个 TASK 承担，仍保留同一个 REQ。已有需求的规则或验收变化需 CR 记录影响，修改规范后更新契约、设计、TASK 和 TC。多个需求冲突必须先消除冲突，不能由开发者自行择一实现。

Git 保存版本历史；BL-001 指本次规范集合，发布以发布记录和 Git 标签固定；不要逐次复制整套文档。
