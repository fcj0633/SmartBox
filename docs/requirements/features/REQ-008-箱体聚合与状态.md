## 背景和目标

多个 node_id 归属一个 box_id，箱体视图组合环境、姿态、定位、门状态、哨兵与告警。

## 业务流程

输入采集或授权请求 → 校验身份和数据质量 → 业务判断/执行 → 记录事件或结果 → 按权限展示。采集、持久化及网络相互解耦。

## 功能规则

1. 箱体预配置必需 ENV/POSE 节点，node_id 全局唯一且固定归属；未注册或箱体不匹配消息拒绝。
2. 90 秒未收到有效心跳/数据标记节点离线；有效 MQTT LWT 可提前标记离线。重新收到数据更新在线状态。
3. 接收时间用于在线判断，不以可伪造的设备 ts 判断在线。历史补传不推进最新业务快照。
4. 快照每字段保留 observed_at、received_at、valid、stale、src；默认 5 秒无新遥测标记 stale，在线与数据新鲜度分开。
5. 箱体返回 online_mask，同时独立提供 connectivity、alarm、sentry、door 状态，不用单一状态互相覆盖。
6. 只有一节点在线时保留可用字段，缺失字段标注不可用；不得把历史缓存显示为当前实测。
7. 事件流水支持类型、时间、分页；历史轨迹支持时间区间；使用稳定排序键保证翻页不因同秒事件跳漏。

## 异常与降级

无效输入不冒充正常数据；错误保留诊断和时间质量。网络离线保持本地能力，网页标注过期和降级。涉及跨端执行的成功必须以实际回执为准。

## 验收标准

单箱体双节点正确聚合；单节点离线、过期字段、历史补传与恢复均显示准确；告警和布防可同时存在。

测试预期和实际结果分开；关联用例见 [测试用例目录](../../testing/cases/README.md)。
