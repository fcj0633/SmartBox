## 背景和目标

在资源限制内保存事件，恢复后可靠补传；把容量内保证与溢出损失明确分开。

## 业务流程

输入采集或授权请求 → 校验身份和数据质量 → 业务判断/执行 → 记录事件或结果 → 按权限展示。采集、持久化及网络相互解耦。

## 功能规则

1. 每节点至少保存 64 条未确认事件，FIFO 补传；不把每秒遥测都写成持久事件。
2. 事件身份 node_id+boot_id+event_seq；boot_id 持久化递增且不得在同节点复用；event_seq 使用 uint32，耗尽前切换持久化的新 boot_id。
3. boot_id 持久化失败时停止生成声称唯一的新事件并上报存储故障；节点角色和 node_id 变更需维护操作。
4. 事件先可靠写入本地，再进入补传队列。后端事务成功（重复事件确认已存在也算）才发送业务 event_ack；MQTT PUBACK 不能删除事件。
5. 后端唯一约束防重复；告警/融合等派生工作可恢复执行，只有收到 MQTT 消息但数据库回滚时不发成功确认。
6. 容量内未确认事件不丢；满后覆盖最旧未确认事件，递增持久化 overflow_total 并暴露覆盖序号范围。后端和界面显示损失，不再宣称完全无损。
7. 写入、确认删除和索引更新需可掉电恢复；具体 KV 布局与一致性方案在专项验证后冻结，禁止假定单次 KV 写天然原子。
8. 补传保留原事件时间、时间质量及 boot_id，增加 replayed 标记；无法恢复 UTC 时不虚构精确时间。

## 异常与降级

无效输入不冒充正常数据；错误保留诊断和时间质量。网络离线保持本地能力，网页标注过期和降级。涉及跨端执行的成功必须以实际回执为准。

## 验收标准

断网容量内补传不丢不重；重复确认无害；64/65 条边界可见；写入和确认过程中掉电 10 次后索引及 CRC 可解释；不得在 KV 未验证时宣称通过。
