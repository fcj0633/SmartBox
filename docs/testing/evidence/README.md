# 验收证据：来源、索引与归档

证据用于证明“哪个版本在什么环境做了什么，结果如何”，不是预期结果或截图数量。本目录保存约定和可脱敏的小型索引，原始日志、固件、截图和运行清单放忽略的[artifacts](../../../artifacts/README.md)。Git中的[报告](../reports)只保留摘要、限制和证据定位。

## 1. 证据最少记录什么

| 信息 | 内容与作用 |
|---|---|
| 来源与范围 | 软件单元、模拟、真实传输、真实数据库/浏览器或实物板端；说明不能证明的部分 |
| 输入版本 | 源码提交；有未提交改动时用差异/源码快照指纹，不能把后提交号冒充镜像内版本 |
| 运行标识 | 日期/时区、环境工具版本、命令/场景、实际执行者、用户物理确认（若需要） |
| 文件清单 | 仓库相对证据路径、大小、SHA256；固件另含角色、节点及镜像哈希 |
| 关联 | REQ/TASK/TC和具体报告章节，操作号/事件唯一键等脱敏业务标识 |
| 实际结果 | 成功、失败、未执行、部分验证及已知限制，保留原始失败记录 |
| 收尾 | 自启动进程、端口、数据库/SDK恢复结果；恢复失败不能隐藏 |

运行目录可用`artifacts/{阶段}/{唯一运行编号}/`，编号可带日期和场景。示例路径是命名建议，不代表现成可用证据；工具要求新目录时不可复用旧结果。

## 2. 怎样证明不同结论

编译/链接日志证明产物形成，烧录成功证明传输完成，启动身份/传感器日志证明板运行；真实动作还需匹配操作与回执，以及用户观察。HTTP202、MQTT PUBACK、数据库保存和执行回执是不同事实，不能相互替代。

用例[TC](../cases/README.md)给标准，报告给本次结果；某任务通过部分软件检查不升级整份TC。LWT离线与90秒静默、受控时钟与真实等待、Mock输出与物理动作分别记录。未取得证据写“未执行/待验证”，UNKNOWN不算正常。

## 3. 分享、脱敏与维护

报告使用相对索引，跨电脑分享另提供脱敏证据包和SHA256清单，不只给对方打不开的本机绝对路径。本地证据没有随Git克隆是正常现象；路径失效或文件缺失时明确指出，不补造“已通过”。

密码、JWT、ticket、设备凭据、私钥、私有配置和可恢复秘密的原始浏览器HAR/trace不得进入报告或Git；定位/账号/网络信息按需要脱敏。只截图已脱敏业务页面，不能用登录页凭据作证据。

文件归档后保持原结果和校验值；纠正错误时解释原因并关联新记录，不覆盖失败成成功。原报告/发布反映当时范围，当前状态从根README/当前进度进入。保留最小必要证据，不把SDK、依赖或大量原始日志塞进Git。
