## 4. 失败发现及修复复验

首轮 SQL 验收客户端仍指定3306，暴露了独立端口支持缺口；按配置端口修复。MySQL 监听早于初始化文件执行，改为真实认证查询成功后移除文件；Windows 子进程改用本轮实例的认证正常关闭。

中文路径下旧 Broker 会校验 UTF-8，却不能用 UTF-8 绝对路径打开密码文件。最终使用相对引用和明确工作目录，不依赖8.3别名、不复制到公共目录、不修改ACL；旧ASCII绝对配置兼容。

管理器状态更新为UTF-8后，Windows默认解码导致停止检查失败；已统一读取UTF-8。失败运行遗留的记录经创建身份、子进程和端口核对后显式归档，再在同一私有实例恢复验证，不自动删除锁或结束外来进程。

最终软件部署结果由初次新目录完整构建/集成/浏览器结果与显式 resume 的统一管理器复验共同组成；报告保留失败记录，不宣称一次无故障通过。
