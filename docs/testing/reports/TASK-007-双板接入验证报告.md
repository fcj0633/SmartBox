## 4. 断电、静默与恢复

### 4.1 ENV断电与重新供电

用户只断开ENV，POSE持续上报。Broker于1794060821记录ENV超时并发布LWT online=false，后端ENV离线、箱体PARTIAL，网页“部分可用”、旧环境值STALE，POSE仍FRESH。此场景存在LWT，不替代独立90秒规则。

### 4.2 无LWT的实际90秒静默

仅停止本轮拥有的项目Broker及其旧监督进程，核对PID、父进程、可执行文件和专属配置路径后操作；后端、网页、MySQL和两板保持运行。Broker停止期间没有向后端交付LWT，后端最后接收时间在整个确认中断窗口保持不变。

实际观察104.656秒，90秒以前样本仍在线；首个离线观测为ENV最后活动后90579ms、POSE91139ms（约2秒轮询粒度），最终双节点离线、网页离线。Broker恢复后两板重新订阅并上线，boot262149/262146均不变，网页恢复在线；串口显示断网期间仍采集且错误/错过未新增。

本地临时检查脚本首次断言失败：停Broker前的HTTP快照与停进程前最后几条合法消息存在竞态，不能要求与停前快照接收时间完全相同。保留`result.json`的原AssertionError，逐条重新核对停Broker后的首个快照至末尾接收时间恒定、真实90秒边界及恢复；`verified-summary.json`记录复核通过。没有改阈值、加速时间、删除失败记录或把初次脚本说成一次全通过。

证据：`no-lwt-90s-01/outage-timeline.json`、`verified-summary.json`、`recovery-timeline.json`、`web-offline.png`、`web-restored.png`，以及`serial/recovery-COM6-01.log`、`recovery-COM7-01.log`。

1. 初次HiBurn加载失败0xC35A69A5，当前SDK定义为通用失败，非单独的YMODEM超时代码A6。旧镜像用户实烧成功；新镜像同字节换较短路径并重新选择后烧录成功，不能据此断言确切路径长度限制或指责用户流程。

3. Wi-Fi扫描结果容量与WPA2映射兼容问题通过项目SDK适配修复，不改SDK。用户将热点切为WPA2，但未证明WPA3是唯一原始故障原因。
4. 首次补光操作3cc48db4-1776-4593-9454-113cc990832c超时并伴随重启，用户观察两次半秒短亮。日志PC=0、processing任务、溢出标志0；根据调用帧分析存在网络栈压力，但不声称唯一根因已证明。解析临时缓冲移至受检堆分配，网络线程栈8KB，采样/处理4KB；组件与实际后续输出无重启。
5. 校时首次失败后外层错误地阻塞64秒重试，修复为独立重试调度；板端从UNSYNCED恢复SNTP，过期命令拒绝/非法JSON不重启。
6. 第二次补光588123da-6bb6-402b-b9ac-0990d35df69c明确invalid_params，用户确认未亮。只发关闭动作进行时间对照，定位到额外now<issued的零时差限制（实测约263ms偏差）；现行契约未将创建时间定义为预约起点，移除该额外检查，保留有效期/未校时/过期规则。未回写冻结契约、改系统时钟或引入新业务容差。最终正常签发的关闭、补光/风扇/指示灯通过。
