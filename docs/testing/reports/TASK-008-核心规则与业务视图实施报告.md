## 结果摘要

TASK-008 已完成固件规则代码、后端融合/告警/查询视图、模拟器规则场景和网页状态展示的首轮实现。ENV/POSE 均已在真实 OpenHarmony SDK 中编译链接；Ubuntu GCC 宿主规则测试、模拟器测试、前端单元与浏览器隔离测试、契约和文档检查通过。

## 已实施内容

- `firmware/domain/sb_rules.c` 与 `firmware/include/sb_rules.h` 新增纯 C 规则模块，接入管线和命令处理：环境连续帧阈值/回差、姿态校准与分级、冲击合并、光照/倾角开合证据、MOCK 定位模式和围栏、哨兵状态及灯光快速提示。事件只进入易失候选缓冲，不经真实 MQTT 发布。
- 哨兵快速异常只启动对应节点的灯光 10 秒，不启动风扇；事件级别按 [CR-005](../../management/changes/CR-005-哨兵快速提示与事件级别.md) 执行。
- 后端新增 V10～V12 迁移及 `DomainEventWorker`，实现门证据入账、两秒配对/结论、支持事件的告警活动状态、派生视图和快照查询。没有判断结果时仍为 `UNKNOWN`；门相反证据、哨兵恢复等未决语义没有自行补定。
- Python 模拟器加入可重复的 TASK-008 规则事件场景；网页详情展示真实返回的门结论、置信度、告警活动级别和历史标记。Playwright 隔离测试同步到当前页面用语；测试配置支持单独指定前端地址和证据目录。
- 新增 [CR-005](../../management/changes/CR-005-哨兵快速提示与事件级别.md)，记录用户已批准规则，不修改冻结契约和 V1～V9。
