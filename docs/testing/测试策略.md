# 测试策略

基线 BL-001；规则见需求，报文见 contracts。用例编号在 [用例目录](cases/README.md)，当前业务用例未执行。

## 分层

1. 规则测试：模拟采样和时间，验证去抖/回差、姿态、围栏、融合及状态机。
2. 契约与集成：真实 Broker、Spring Boot、MySQL，验证事务、唯一键、确认、权限、断线及WebSocket投影。
3. 板端：真实编译/链接/烧录/采集/输出/资源分阶段取证。
4. 最终系统：双板、网页、网络故障、掉电及24h稳定性。

P1 可使用模拟节点，不需要开发板前置检查；模拟数据必须标记。涉及存储、采样或硬件输出的结果只在真实验证后通过。

## 报告与完成标准

报告包含环境、源码/产物版本、关联需求/TC、输入、步骤、预期、实际、证据、结论和缺陷。一个 TC 可能有多个子场景，任何必需子场景未执行不能标为全部通过。

P0 仅检查原文哈希、目录、链接、编号/追踪及示例基本一致性，不运行业务测试。不为占位目录编造单元测试。P1 开始引入与实现风险相称的测试。

质量验收按 NFR：100次时延、64/65条边界、10次掉电、30分钟断网及24h连续；容量内与溢出分开报告，硬件假设不代替证据。
