# 网页启动与首轮验收

设计和范围见[TASK-006](../tasks/TASK-006-网页与首轮闭环验收.md)，服务准备见[服务端闭环指南](服务端闭环启动与验收.md)，报文以[当前有效契约](../../../contracts/effective/README.md)为准。以下命令在Windows项目根目录执行。

## 安装与检查

使用现有Node 24.14.0和npm 11.9.0，不升级系统工具。前端依赖只安装至frontend/node_modules；依赖锁纳入Git，浏览器、构建、日志和截图放忽略的artifacts。首次安装执行：

```powershell
.venv/Scripts/python tools/frontend.py install
```

统一安装入口使用npm ci及锁文件，并安装匹配的Chromium到artifacts/task006/browsers，不改日常浏览器。若需要单独补装浏览器，可在frontend目录执行以下命令：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = [System.IO.Path]::GetFullPath('../artifacts/task006/browsers')
node node_modules/playwright/cli.js install chromium
```

不将系统已有的其他Chromium缓存当作版本兼容证明。精确版本及间接依赖兼容处理见[版本矩阵](../environment/工具与依赖版本矩阵.md)。

## 本地开发启动

先按服务端指南构建、核对开发库和受控初始化。复用secrets/backend.local.json、secrets/mqtt.local.json及其指向的本地初始化账号；不把密码填入本文或前端环境变量。不要以root启动应用。

分别在终端启动：

```powershell
.venv/Scripts/python tools/mqtt.py broker --config secrets/mqtt.local.json
.venv/Scripts/python tools/backend.py run --profile dev --mqtt-config secrets/mqtt.local.json
.venv/Scripts/python tools/mqtt.py node --role ENV --config secrets/mqtt.local.json
.venv/Scripts/python tools/mqtt.py node --role POSE --config secrets/mqtt.local.json
.venv/Scripts/python tools/frontend.py dev
```

网页访问[本地工作台](http://127.0.0.1:5173)，健康检查使用后端8080。Vite代理/api与/ws到回环8080并保留Origin；不开放防火墙。端口1883/8080/5173被占用时检查归属，不结束其他进程或静默改端口。

使用本地初始化文件中已有账号登录。Token只在内存保存，刷新需重新登录；四角色由后端决定，网页不提供角色选择。退出会清理会话、缓存、订阅和命令草稿。网页及模拟器均不是Flash或板端验收。

## 自动复验

```powershell
.venv/Scripts/python tools/frontend.py check
.venv/Scripts/python tools/frontend.py build
.venv/Scripts/python tools/frontend.py browser
.venv/Scripts/python tools/frontend.py integration --profile test --allow-test-reset --run-dir artifacts/task006/新的唯一目录
```

check运行类型检查及单元/组件；build生成frontend/dist。browser只启动自身Vite和浏览器，使用受控响应进行隔离测试，不代表真实后端通过。integration使用真实项目测试库、Broker、后端、两个独立模拟进程及网页，要求显式test配置和清理同意；新证据目录必须位于artifacts内。缺少配置或依赖直接失败，不静默跳过。

集成前停止自己手动启动的开发进程，使三个端口空闲。后端集成测试、TASK-005联调和TASK-006联调不能并行操作smartbox_test。测试库可按显式同意清理；smartbox_dev不参与清理。MySQL原服务保持运行。

真实测试通过本地文件屏障控制自身节点暂停/恢复、Broker重启、后端中断和测试授权撤销，没有新增测试HTTP接口。测试授权撤销仅发生在smartbox_test；重新执行集成会重置测试运行数据并恢复本场景撤销的授权，不覆盖密码或修改开发授权。

## 浏览器验证与证据

F01～F14的适用结果分别记入任务报告：四角色、双箱体、五类控制、同键重试、部分成功/迟到事实、断连恢复、未知状态和两个桌面尺寸。真实静默超过90秒与隔离时钟测试分开记录，LWT若提前到达也不能假称已经等待90秒。

原始日志与脱敏截图放本地artifacts，受控报告只保存摘要、指纹和索引。Playwright关闭trace/HAR/video及自动失败截图，显式截图不保存登录凭据；浏览器私有输入含测试账号，只能保存在忽略目录，不提交。命令测试的成功是模拟节点执行成功，不等于实体开门、真实校准或防盗通过。

环境/姿态5秒、定位15秒、节点90秒保持；没有融合/告警判断时显示未知，不显示正常。完整历史、轨迹和CSV页面由TASK-010完善，网页不创建无API依据的管理或取消接口。

## 停止与恢复

自动入口只清理自己创建并持有进程句柄的浏览器、Vite、后端、节点及Broker，检查端口释放；不停止共享MySQL和旧Mosquitto服务。手动开发按各终端的正常退出方式结束。数据库、本地配置、节点主机代次和本地证据保留。

若机器中断，先核对实际端口和进程归属，再按原启动顺序恢复；不以本次桌面重启替代设备掉电验证。命令整体超时终态固定，节点可能已有迟到执行；恢复后查询真实结果，不自动重发为新动作。

定向补查可在integration参数中增加--scenario authorization，验证真实跨箱体拒绝及非空业务WS/四角色HTTP的有效Schema；它不能代替完整主场景及真实90秒观察。完整结果见[TASK-006报告](../../testing/reports/TASK-006-网页与首轮闭环验证报告.md)。
