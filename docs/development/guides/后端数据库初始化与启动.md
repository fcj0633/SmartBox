## 构建、初始化和运行

先确认JAVA_HOME指向JDK21实际安装目录，Java/Maven在PATH，本地MySQL运行。现有Windows PATH里的Oracle java启动器可能产生额外子进程；工具用JAVA_HOME/bin/java.exe直接管理实际进程。

```powershell
python tools/backend.py unit
python tools/backend.py build --profile dev
python tools/backend.py bootstrap --profile dev
python tools/backend.py run --profile dev
```

unit只执行mvn test，不读取本地数据库凭据。build执行mvn verify（不包含it profile），产物backend/target/smartbox-backend-0.1.0.jar。bootstrap以非Web方式运行显式初始化并正常退出，相同输入可重跑。run启动127.0.0.1:8080，使用终端Ctrl+C停止。Flyway在连接时校验/迁移，禁止clean、自动repair或改写已应用迁移。

本机JDK的AF_UNIX内部连接出现Invalid argument，已用本地开关SMARTBOX_WINDOWS_TCP_SELECTOR处理：工具仅为本次Java进程设置jdk.net.unixdomain.tmpdir到忽略目录中的普通文件，使JDK使用内置TCP回退；不改系统网络、JDK或用户全局环境。其他主机无此问题时可关闭该本地开关，不能据此宣称生产部署兼容性已验收。

## 真实MySQL与HTTP复验

```powershell
python tools/backend.py test --profile test --allow-test-reset
.venv/Scripts/python tools/backend.py smoke --profile dev --report-dir artifacts/backend/TASK-003/final-http
```

第一条执行mvn verify -Pit，包括纯单元和真实MySQL/HTTP集成。必须同时满足test profile、精确smartbox_test URL、实际库与运行账号及显式清理开关；仅删除test业务数据再初始化，保留角色/迁移历史，不DROP库或停MySQL。它会重新创建八个测试账号，勿把测试库当长期业务库。没有配置或MySQL时检查失败，不静默跳过。

第二条用既有.venv中的Schema依赖，要求8080空闲，自行启动真实JAR、验证冻结响应Schema和授权错误，最后停止自己启动的进程并确认端口释放；不会停止占用端口的其他程序。登录秘密和JWT仅在内存，摘要不保存响应原文。Schema依赖安装方式沿用版本矩阵。

Flyway初次执行V1～V3建立13表，V4补齐回执时间约束的非空条件；已有库重跑不改账号或数据。迁移校验失败保留现有结构/history、诊断后新增受控迁移，不覆盖已应用脚本。MySQL DDL可能部分提交，不通过自动清空解决失败。
