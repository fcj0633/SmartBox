## TASK-007烧录与双板联调顺序

详细实现与验收以[TASK-007](../tasks/TASK-007-双板实际采集与输出接入.md)为准，本指南只维护操作导航。当前任务待开始，本轮没有构建或烧录。

1. 启动Ubuntu，复用本机忽略连接说明核对SSH、SDK和映射；通过既有工具预览、备份、同步和构建，恢复原入口/输出/厂商状态。

3. 先ENV后POSE，在HiBurn选择已确认的端口和对应产物，按工具当次流程配合复位/重连；烧录成功后释放端口，再采集启动身份与串口日志。不得默认使用旧COM号或把GUI操作当已自动完成。
4. 停止同身份模拟节点；板件连接可互访的2.4GHz局域网，Broker使用电脑指定网卡地址，后端/网页仍回环监听。需要的受限防火墙配置须有记录和恢复方式，不关闭整体防火墙。

6. 分别留存编译、烧录、启动、采样、联网与实物证据。清理本轮自启动进程和临时规则，保留项目库、私有配置与证据，不停止共享MySQL或修改旧Mosquitto服务。

前述学习目录已有HiBurn/CH340工具不代表驱动已识别；只有串口未正常识别时再检查线材与驱动。无需先重做全部官方实验。

## TASK-007本轮可执行入口与等待点

TASK-007已完成软件与双角色构建，尚待ENV烧录确认及双板验证，详见[阶段报告](../../testing/reports/TASK-007-双板接入验证报告.md)。前述TASK-007“本轮仅文档”指设计整理时；本段记录当前实施状态。

在仓库根目录使用项目.venv执行：

```powershell
.venv/Scripts/python tools/hardware.py check
.venv/Scripts/python tools/hardware.py prepare
.venv/Scripts/python tools/hardware.py broker --run-dir artifacts/task007/NEW-BROKER-RUN
.venv/Scripts/python tools/backend.py run --profile dev --mqtt-config secrets/hardware/mqtt.local.json --hardware-mqtt
.venv/Scripts/python tools/frontend.py dev
```

prepare只在首次准备或需要新配置/新代次区间时执行，之后必须构建对应镜像。Wi-Fi在secrets/firmware.local.json，节点账号复用secrets/mqtt.local.json，生成头文件和硬件配置均忽略；不在命令行填密码。Broker为回环和指定LAN网卡各设监听，拒绝匿名及配置漂移；默认模拟工具仍只接受回环配置。若电脑IP变化，重新核对配置并构建，不让板端继续使用旧地址。

硬件联调前核对并按需要建立受限防火墙规则，记录规则及恢复方法；上述broker命令不会自动关闭防火墙或修改旧服务。端口占用时停止操作，不结束其他程序。

烧录使用当前会话确认的角色归档，先ENV后POSE。HiBurn退出后才打开串口采集，采集提示SERIAL_READY后再请用户按复位；采集不发送串口指令，DTR/RTS关闭。示例输出文件须使用新名字：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/capture_serial.ps1 -Port COM6 -Output artifacts/task007/serial/ENV-NEW-BOOT.log -Seconds 60
```

COM号为当次已识别目标，不能把示例COM6当作所有板默认值。烧录/复位/实物观察都需用户明确回复完成，再读取日志与核验；烧录成功不等于驱动、联网或物理动作已通过。不能整片擦除后重复使用旧配置；擦除或启动记录恢复需先按任务7重新预留代次、重建镜像。

## ENV首次烧录加载失败的排查记录

用户提供截图出现Ready to load at 0x10A000及重复load fail 0xC35A69A5，尚无成功烧录证据；COM6已识别且曾能打开接收。后续已在当前SDK的boot/commonboot/hi_boot_err.h核对该码为HI_ERR_FAILURE（通用失败），而YMODEM超时为0xC35A69A6；不据此断言波特率、芯片或扩展板故障。

按[BearPi-HM Nano官方十分钟上手教程](https://bearpi.cn/dev_board/bearpi/hm/nano/software_OpenHarmony/BearPi-HM_Nano%E5%8D%81%E5%88%86%E9%92%9F%E4%B8%8A%E6%89%8B.html)第九节，烧录Baud为921600，Auto burn勾选，Connect后按板上的实体RESET；这是与运行日志115200不同的设置。不要把HiBurn窗口下方的Reset或板上USER按键当作实体复位操作。烧录以Execution Successful为成功依据，再Disconnect释放端口。

当前先停止自动重试，核对参数和实体复位时序；若再次失败，再分步核对低速串口对照、数据线/直连USB与供电。HiBurn占用COM时不同时运行日志采集，不在此阶段更换Flash地址、整片擦除或修改SDK。项目镜像内15360字节loader片段与恢复后的原SDK产物相同，SHA256为8dc8ae6d775388d2c9518dcae008c3117b1600cea3f702f0fb3f00bc0bc72cdf，尚不能由此证明后续烧录一定成功。

用户按流程重试仍失败时，停止重复相同操作，先取此前当前板上烧录成功的镜像做单因素对照。当前ENV包头CRC16、长度/填充与分段边界均已核验，loader/boot与恢复的旧SDK产物相同；恢复产物未实测前不能叫已知良品。只有旧/新镜像结果分离后，才进一步定位包读取/工具兼容或USB双向传输、供电和扩展板影响；不同时更换多个因素。
