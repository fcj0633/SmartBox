# 编译、烧录与联调流程

状态：TASK-002双角色骨架已实际编译/链接并恢复原学习环境，尚未烧录/运行。当前产物只提供Mock输入和禁用网络。完整流程使用tools/build_firmware.py，参数与恢复方法见[工具说明](../../../tools/README.md)。不能把历史学习产物当项目固件。

1. TASK-002 记录当前 SDK sample/BUILD.gn 的启用项，受控新增 logistics_box；同步前预览差异。
2. 在 Ubuntu 的 /home/bearpi/project/bearpi-hm_nano 内执行现有命令 python build.py BearPi-HM_Nano。命令用于既有 SDK，不能在 Windows 映射目录直接执行。
3. 分别选择 ENV/POSE，确认本次 BUILD SUCCESS、产物更新、角色身份；归档 Hi3861_wifiiot_app_allinone.bin、SHA256、提交号、角色和构建日志，避免第二次构建覆盖第一次后取错。
4. P2 接板，按实际 CH340 串口选择 HiBurn；先确认目标板角色和产物，不默认历史 COM6。
5. 烧录后释放端口，再开115200串口，记录启动身份、采样、联网和回执；固件错误与串口问题分别定位。
6. 联调前核对板端可达 Broker 地址、账号ACL、网络隔离；先看真实上报再检查数据库与网页。不把电脑模拟消息当板端消息。
7. 脱敏日志保存 artifacts，报告引用可归档证据。未成功的阶段保留实际错误，不使用预期截图代替。

P1软件与模拟闭环已交付；服务端与网页的实际操作分别见[服务端指南](服务端闭环启动与验收.md)和[网页指南](网页启动与首轮验收.md)。这些软件结果不能代替板端验证。

## TASK-007烧录与双板联调顺序

详细实现与验收以[TASK-007](../tasks/TASK-007-双板实际采集与输出接入.md)为准，本指南只维护操作导航。当前任务待开始，本轮没有构建或烧录。

1. 启动Ubuntu，复用本机忽略连接说明核对SSH、SDK和映射；通过既有工具预览、备份、同步和构建，恢复原入口/输出/厂商状态。
2. ENV/POSE分别归档产物、版本与SHA256；断电安装IA1/SC2，贴角色标签，逐块插入建立板号—角色—COM对应表。
3. 先ENV后POSE，在HiBurn选择已确认的端口和对应产物，按工具当次流程配合复位/重连；烧录成功后释放端口，再采集启动身份与串口日志。不得默认使用旧COM号或把GUI操作当已自动完成。
4. 停止同身份模拟节点；板件连接可互访的2.4GHz局域网，Broker使用电脑指定网卡地址，后端/网页仍回环监听。需要的受限防火墙配置须有记录和恢复方式，不关闭整体防火墙。
5. 先验证单板采集、校时状态和输出，再双板运行至少5分钟；核对入库、网页、输出期限与回执，并由用户确认真实动作。
6. 分别留存编译、烧录、启动、采样、联网与实物证据。清理本轮自启动进程和临时规则，保留项目库、私有配置与证据，不停止共享MySQL或修改旧Mosquitto服务。

前述学习目录已有HiBurn/CH340工具不代表驱动已识别；只有串口未正常识别时再检查线材与驱动。无需先重做全部官方实验。
