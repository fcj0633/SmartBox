# 编译、烧录与联调流程

TASK-007 已完成基础真实双板链路。真实固件支持 IA1/SC2 采集、Wi-Fi/MQTT/SNTP 与 output；GPS 仍 MOCK，完整算法和 Flash 事件可靠性未完成。历史过程见[TASK-002报告](../../testing/reports/TASK-002-固件骨架验证报告.md)及[TASK-007报告](../../testing/reports/TASK-007-双板接入验证报告.md)。

先完成[完整部署指南](../../delivery/deployment/开发者完整部署指南.md)的工具、SSH、SDK、数据库和软件准备。日常代码只修改主仓库 firmware；SDK sample/logistics_box 是单向同步副本，不覆盖学习实验。

## 1. 环境、角色与私有配置

| 角色 | 扩展板 | 身份 | 能力 | 实际输出 |
|---|---|---|---|---|
| ENV | IA1 | BOX-0001-ENV | 71 | 补光、风扇 |
| POSE | SC2 | BOX-0001-POSE | 120 | 指示灯 |

Windows 使用项目 .venv，Ubuntu 通过密钥 SSH 编译。映射盘可用于浏览，新入口不依赖映射。核对 secrets/workspace.local.json 的当前地址、外部私钥、SDK 与三个工具目录；构建只补充子进程 PATH，不修改 .bashrc 或升级 SDK。

真实板接入前停止同身份模拟节点。在忽略目录创建 secrets/firmware.local.json，填写实际值：

```json
{
  "format": 1,
  "wifi_security": "WPA2_PSK",
  "wifi_ssid": "YOUR_2_4GHz_SSID",
  "wifi_password": "FILL_LOCALLY_8_TO_63_BYTES",
  "broker_ipv4": "192.168.1.100",
  "allowed_subnet": "192.168.1.0/24",
  "ntp_server": "YOUR_REACHABLE_NTP_HOST"
}
```

地址必须属于电脑实际网卡，子网包含该地址且为 /16 或更窄，不直接使用示例地址。NTP 填可达主机名，不带协议。网络需为可互访的 2.4GHz WPA2；SSID 为 1～32 UTF-8 字节，密码为 8～63 字节。check 只校验形状，不证明可达。

```powershell
.venv/Scripts/python tools/hardware.py check
.venv/Scripts/python tools/hardware.py prepare
```

prepare 读取本地 MQTT 账号、项目库最高已知 boot 和区间账本，先预留区间再生成忽略的 sb_local_config.h。缺项目库或客户端时先完成数据库准备，不用 root 替代运行账号。重复 prepare 会消耗新区间，只在首次或确需新配置/区间时执行，启动 Broker 不需要重做。

## 2. 同步、双角色编译与恢复

```powershell
.venv/Scripts/python tools/project.py firmware-build
```

顺序为源码身份与指纹、SSH 临时输入、差异预览、备份 SDK 入口/旧输出/厂商子树、ENV 编译链接并归档、POSE 编译链接并归档、恢复入口/输出/哈希/Unix 权限。

Ubuntu 在 SDK 内执行 `python build.py BearPi-HM_Nano`，不是在 Windows 进入 Z: 后运行 Python。新 SDK 的初始输出可能为空，恢复后应仍为空；旧 SDK 恢复它原来的状态，不固定使用原作者的学习目录或数量。

一套源码通过互斥 GN 配置生成两个角色。每个角色需独立的 build.log、manifest.json、product、最终链接对象、映射和镜像 SHA256。同一 bin 改名不算双角色。源码 zip 中 SOURCE.json 提供提交及文件清单，无 .git 也可追溯，修改后记录偏差。

中断后保留 run.json、本地备份和远程工作目录。沿用当次连接、SDK、transport，给 tools/build_firmware.py 传 `--recover` 与原运行目录。不要删除锁或覆盖现场；并发修改时工具拒绝恢复。[工具导读](../../../tools/README.md)说明传统映射接口和产物边界。

## 3. 逐板烧录与串口

1. 断电装好扩展板并标记，先只连接 ENV，确认新增 CH340 COM。识别异常时检查数据线、驱动及虚拟机 USB 抢占，不默认历史 COM。
2. 选择本次 ENV 归档中的 Hi3861_wifiiot_app_allinone.bin，核对 SHA256。建议复制到短 ASCII 路径并重新选文件，避免 HiBurn 路径兼容问题；不使用恢复后的旧 SDK 输出代替。
3. HiBurn 选择文件、端口、921600、Auto burn，Connect 后按板上实体 RESET；窗口 Reset 和 USER 键不能代替。
4. 看到 Execution Successful，Disconnect/退出 HiBurn，释放串口再复位启动。HiBurn 与日志采集不能同时占用一个 COM。
5. 用 115200 核对启动身份，再对 POSE 重复。编译、烧录、启动和实物动作分别记录。

官方入口：[BearPi 十分钟上手](https://www.bearpi.cn/dev_board/bearpi/hm/nano/software_OpenHarmony/BearPi-HM_Nano%E5%8D%81%E5%88%86%E9%92%9F%E4%B8%8A%E6%89%8B.html)。历史加载失败和短路径重选后成功保留在报告，不据一次错误码推断硬件损坏。

串口采集示例，COM6 必须替换为当次端口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/capture_serial.ps1 -Port COM6 -Output artifacts/my-board-run/ENV-BOOT.log -Seconds 60
```

先等待 SERIAL_READY，再复位，输出使用新文件名。不要随意整片擦除或把启动代次清零；擦除、换机和重建配置前先核对账本及服务端代次。

## 4. 双板联网与实际输出

```powershell
.venv/Scripts/python tools/project.py start --mode hardware
```

该模式不启动模拟节点、不自动 prepare、不改防火墙。Broker 绑定指定 LAN 网卡并保留本机访问，后端/网页仍回环。板端使用电脑实际 LAN 地址，不是 127.0.0.1。防火墙规则只针对项目 Mosquitto、1883、适用网络类型和来源子网，记录恢复方式。

先单板验证采集、时间、身份和入库，再两板运行。网页更新不能证明 50Hz，须检查采样统计。ENV 补光/风扇、POSE 指示灯分别通过 output 验证，操作者确认动作和期限关闭，软件核对回执及数据库。勿触碰叶片，不用敲击或摔板制造输入。

未校时仍可采集上报，UTC 保持空值，控制按契约拒绝。真实固件尚不执行完整画像、定位模式、校准和哨兵；模拟成功不能写成真实算法通过。GPS、门/告警 UNKNOWN 与传感器有效性分开解释。

## 5. 收尾与证据

运行 `tools/project.py stop` 或启动窗口 Ctrl+C，保留共享 MySQL、项目库、私有配置和账本。重启遗留记录时先核对进程，再用 `tools/project.py recover-state` 归档死会话；有已登记进程或端口活动时会拒绝，不按旧 PID 直接结束进程。

记录源码、SDK 清单、角色校验、恢复、烧录/启动/动作及限制。原始日志与含本地配置的快照留在忽略目录，分享前脱敏。部署验证不升级完整业务需求、TC 或 TASK-008～010。
