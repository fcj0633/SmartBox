## 1. 任务目标与定位

为固件、后端、网页及模拟节点提供一致、可追溯的工具版本依据和接口契约，减少各端各自解释字段、权限、时间和确认机制造成的返工。任务按开发依赖安排，不按MOD编号排序；本任务跨多个业务模块，但只承担接口准备。

本任务完成后，A可以据此开展TASK-002双角色固件骨架，B可以开展TASK-003后端骨架、TASK-004模拟节点及MQTT准备；后续TASK-005、TASK-006消费同一契约。后续任务原有依赖、负责人和范围保持不变，B的工作仍按依赖顺序推进。

任务完成不表示关联需求已实现，也不表示服务、数据库、模拟链路或开发板验收通过。

## 2. 范围与交付边界

包含：环境事实核对、官方兼容性调研、精确版本矩阵、现有MQTT/REST/WS契约的机器可读表达、正反样例、静态检查、冻结范围和交接。

业务规范以模块需求为准，协议细节以根目录[contracts](../../../contracts/README.md)为准。机器可读契约是文字契约的可检查表达，差异必须澄清，不能默默建立两套规范。

本任务不实现固件、后端、网页、数据库迁移或运行链路，不安装升级系统工具、不启动服务、不建库、不修改SDK；按用户授权仅在独立.venv安装契约校验依赖。MOD-01与MOD-02的命令参数引用现有需求，不将监测算法、门融合或哨兵业务实现纳入本任务。不以真实开发板测试作为开工条件。

本次已执行接口盘点、版本核对、机器契约、样例和检查工具编写；产出入口见第6节，最终验证结果见第9节。技术细节补齐和取消人工评审依据[ADR-002](../../management/decisions/ADR-002-接口契约细化与自动检查.md)。

## 5. 分步执行计划

S1～S7是本任务内部步骤，不新增全局TASK编号。每步负责人均为B；按本次用户授权由Codex执行，取消人工评审，不代填A/B意见；下表顺序是默认推进顺序。S3～S5复用S1清单及已确定公共定义，遇未决部分按第8节隔离，不跳过必要检查。

### S1 输入核对与接口盘点

- **输入：** 第3节全部资料，重点是现有文字契约和Q清单。
- **动作：** 逐项盘点MQTT上/下行消息、REST全部路由、WS客户端与服务端消息、所有现有控制命令和角色字段投影；为每项登记来源章节、已定义内容、缺口、关联需求及消费端。
- **产出：** 接口覆盖清单和待决项影响表。记录字段为“接口或消息、来源、需求、目标Schema/操作、样例、检查方式、缺口、影响、负责人、所需决定”。
- **检查与完成条件：** 对照契约目录和路由表逐项勾对，确认无漏项；缺失定义不以自行填入默认值的方式关闭。

### S2 工具与依赖版本矩阵

- **输入：** 环境清单、既定技术栈、S1接口及工具需求。
- **动作：** 只读核对已安装版本；查询官方兼容性资料并记录访问日期。覆盖Java 21、Spring Boot/Security、Maven、MyBatis及适配组件、Flyway及MySQL支持组件、MySQL 8、Node、Vue、TypeScript、Vite、Router、Pinia、Element Plus、Mosquitto，以及拟采用的契约校验工具。固件记录现有SDK版本或可追溯来源、编译工具链及构建方式，不升级SDK。
- **产出：** 版本矩阵，包含组件、所在环境、已安装版本、拟采用精确版本、兼容约束、官方来源、选定原因、验证方式、验证结果和阻塞项；明确JSON Schema/OpenAPI规范版本与校验器支持范围。
- **检查与完成条件：** 区分“已安装”“拟采用”“已验证”；版本选择有来源且无浮动表达。官方兼容声明不当成项目已运行证据；无法核实的兼容组合不得写成已验证。

### S3 MQTT机器可读契约

- **输入：** MQTT文字契约、现有示例、S1清单和S2选定规范。
- **动作：** 定义公共身份、能力、时间与空值约束，再覆盖遥测、心跳、事件批次、精确业务确认、命令、执行回执、可用性及箱体状态消息；整理每种现有命令的参数、能力要求和错误分支。
- **产出：** MQTT Schema、每类消息和命令的有效及无效样例、结构以外的行为规则清单。保留原examples.json语义，不为使样例通过而修改原规则。
- **检查与完成条件：** 正样例结构通过，反样例按指定原因失败。JSON UTF-8字节上限、Topic/MQTT包容量、跨字段时间比较、能力匹配及状态转换另列检查；不能只用字符串长度代替字节容量，也不能用结构检查证明事务确认和实际执行。
