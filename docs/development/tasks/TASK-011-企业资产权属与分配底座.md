## 工作内容（首轮 DEMO 切片）

**目标：实际能在网页看到“企业箱体 → 分配骑手 → 骑手的箱体列表”。** 不做完整 SaaS 企业/成员系统。

- 复用已有 `users`、`boxes`、Spring Security 和 MySQL；受控初始化一个企业、一个企业管理员、一个骑手及一个个人拥有者。
- 仅新增演示所需的 `enterprises`、`box_ownerships`、`box_assignments` 三张简单业务表；不实施企业成员邀请、多岗权限、权属转让、复杂分配历史。
- 企业管理员能查看本企业箱体、分配或收回使用权；骑手能查看自己的个人箱体及被分配箱体。
- 服务端以实际用户和当前归属关系校验；不能输入别人的企业/箱号就控制或查看他人的资产；同箱一条有效分配。
- 若箱体已处于 ACTIVE 运输，普通收回直接拒绝并提示“请先结束运输”；**紧急接管 UI 和复杂撤权链路延后**，原 REQ-M05-007 / M06-007 的相关候选验收仍标未覆盖。

## 推荐实现顺序

1. 读取 [演示优先方案](../guides/CR-006-演示优先实施方案.md) 和 [原数据设计](../../design/backend/CR-006-企业箱体与运输任务数据设计.md)，明确与 `user_box_access` 的区别。
2. 在新 Flyway 迁移中仅新增三张最少数据表；使用受控演示种子数据，不修改 V1～V12。
3. 在 Spring Boot 增加最小资产查询、分配、收回和我的箱体接口；不用完整企业管理后台。
4. 用隔离 MySQL + HTTP 跑通一次分配/收回成功及一次越权拒绝；必要时页面接入简单资产列表。
5. 记录实际运行结果；没有运行的其他用例不计通过。

## 验收与不做什么

首轮最低验收以 [TC-013](../../testing/cases/TC-013-企业资产与权限隔离.md) 的 **DEMO 检查**为准。非目标：多企业动态入驻、企业成员管理页面、在线所有权转移、紧急接管工作流、复杂审计报表和全量压力测试。原严格业务规则作为后续候选，不假装本轮已全部实现。
