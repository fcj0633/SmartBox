## 1. 任务目标与当前事实

本任务将TASK-002的双角色骨架接入真实硬件，复用TASK-005/006已有服务和网页，完成P2双板真实采集与输出切片。详细设计集中在本文；总体设计和指南只维护职责与操作入口。

**上行：IA1/SC2 → 板端Wi-Fi/MQTT → 项目Broker → Spring Boot → MySQL → 网页。**

**下行：网页输出命令 → 后端授权 → Broker → 指定板件 → 实际动作 → 执行回执 → 数据库与网页。**

开工基础为TASK-002的Mock/禁用网络骨架；本次已接入真实IA1/SC2、Wi-Fi/MQTT、SNTP和真实输出，完成双板链路实测。当前事实以第10节及实际报告为准，骨架编译和官方例程结果不替代本次板端证据。

本次实施已完成源码、双角色实际编译链接、用户逐板烧录、同局域网双板及现有系统联调。未修改SDK、业务规则、冻结契约或数据库迁移；未创建防火墙规则。

## 4. 固件分层与接口设计

沿用一套C/CMSIS-RTOS2源码，ENV/POSE编译选择互斥，不通过手工反复修改公共头文件切换角色。

| 层次 | 本任务接入职责 | 约束 |
|---|---|---|
| app | 装配真实端口、采样/处理/网络线程及启动门禁 | 默认输出关闭；资源不完整时不进入工作状态 |
| domain | 接收统一真实样本并维护快照 | 保留TASK-008规则入口，不依赖外设寄存器或网络 |
| drivers | IA1、SC2、GPIO和SDK适配 | SDK错误转公共错误；Mock与真实来源分别标记 |
| services | 时间、网络、协议编解码、配置与有界缓冲 | 不把内存保存叫可靠持久化，不伪造发送或执行成功 |
| include | 样本、质量、状态、端口与角色配置 | 扩展真实来源/校时质量需同步调用者及测试，内部类型不另造协议 |
| build | 真实驱动选择、GN及本地配置接入 | 测试替身不得进入生产固件，凭据不进入受控文件 |

保留sb_sensor_read、sb_output_set、sb_clock_get及处理快照接口的职责边界；现有sb_network_poll/publish禁用桩需替换或扩展为真实网络适配，不能返回假成功。

ENV每1秒采集；POSE初始每20毫秒采集，定位按当前Mock模式独立调度。采样线程不做网络I/O、不等待网络缓冲空间、不逐帧打印。处理线程维护按值快照，网络线程统一持有客户端并使用有界发送缓冲。明确定义队列满、丢帧、驱动失败、重连及校时失败计数；具体缓冲和栈大小在实现时按SDK证据核验，不修改既有协议容量。

输出按角色能力校验，默认关闭，使用单调时间执行期限关闭。SDK接口失败不得生成成功回执；同一请求重传不能再次触发动作，过期、保留、身份错误、能力不足或无可信UTC按有效契约拒绝。尚未实现的业务命令明确拒绝，不把模拟器成功语义搬到真实硬件。

传感器无效读数必须保留质量，不用0或上一帧冒充新测量。基础角度值不证明静置校准、姿态分级或冲击判定通过。RAM/Flash沿用NFR口径，不扩大为本轮已实测成绩。

## 5. 网络、身份与联调隔离

开发板连接可与电脑互访的2.4GHz Wi-Fi；Broker地址采用电脑指定网卡的实际局域网地址。板端127.0.0.1指向板自身，不能指向电脑Broker。

后端8080和网页5173保持原有回环监听；项目Broker为板端配置指定网卡监听，并保留电脑侧服务的可达路径。正式调整前核对现有模板与工具，不直接覆盖全局Mosquitto配置或启用旧服务。

如需Windows防火墙规则，限定项目程序、1883端口、网络配置文件和来源范围，记录规则标识、创建前状态及恢复方式；不关闭整体防火墙，不开放后端或网页到局域网。本轮仅设计，不实际调整。

默认BOX-0001，ENV为BOX-0001-ENV、POSE为BOX-0001-POSE，能力配置沿用71/120并核对有效契约中的字段适用性。接入前停止相同身份模拟节点，使用节点独立账号及现有ACL；不拿测试控制账号作板端账号。

Wi-Fi与Broker凭据只通过本地忽略配置加载；生成到SDK的私有配置与产物也不得提交Git或打印秘密。报告只记录配置来源和脱敏状态。后端复用项目库，不重建另一套服务。

上报保持Topic、QoS、retain、容量和时间规则。UTC、单调时间、代次、序号与接收时间职责分开；位置仍MOCK，独立观测标记与15秒口径沿用CR-004。连接在线、采样有效、新鲜度和业务结论分别展示。心跳30秒、服务端无活动90秒离线，LWT与重连按当前契约处理。

网络排查顺序：板端关联/AP地址 → AP隔离和电脑网卡地址 → 指定监听/防火墙 → 认证/ACL → 订阅确认 → 合法上报 → 后端保存 → 网页。校时另查服务器可达性，不用“已联网”推导“已校时”。

## 7. 用户操作与等待点

已确认可同时提供双板并使用同一局域网；下表不要求现在接板，正式执行到对应步骤时再提示具体目标与操作。

| 时点 | 用户操作 | 软件/工具配合 | 继续条件 |
|---|---|---|---|
| 开工准备 | 启动Ubuntu虚拟机，恢复映射或提供可用文件访问路径 | 复用现有SSH密钥，只读检查，不重复配置公钥 | SDK可核对且受控同步路径可用 |
| 接板前 | 准备两块Nano、IA1、SC2和两条数据USB线；断电安装并贴ENV/POSE标签 | 提供对应表，确认扩展板版本与插接方向 | 两套板件和供电明确 |
| 串口识别 | 先逐块插入确认新增COM，再同时接入；必要时处理驱动 | 枚举端口，记录板号、角色、COM；不默认历史串口 | 目标可唯一定位，端口未被其他程序占用 |
| 网络准备 | 将电脑和板件接入可互访网络，在本地忽略配置填写Wi-Fi信息 | 核验监听、ACL、电脑地址与校时路径，不要求秘密进聊天/Git | 2.4GHz可用且无AP隔离阻断 |

| 实物验证 | 遮挡/照亮IA1，缓慢转动SC2；观察补光、风扇和指示灯 | 同时核对串口、网页、数据库与回执 | 物理动作与对应命令一致，有人工观察记录 |
| 故障恢复 | 按提示对指定板断电/重连并恢复供电 | 记录离线/恢复和代次，清理自己启动的服务 | 不影响另一板、共享MySQL或其他项目 |

HiBurn的GUI操作不能预设为工具已能代办；可自动化部分在实际执行时核验，用户只承担必要的选择、复位、插拔和实物观察。烧录完成后释放HiBurn串口，再开串口日志，现有指南使用115200，实际固件设置需一致。

不要求重做全部官方实验；不摔板、不敲击裸板或触碰裸露旋转部件来生成输入。所有物理操作先明确目标ENV/POSE，避免刷错板或接错扩展板。
