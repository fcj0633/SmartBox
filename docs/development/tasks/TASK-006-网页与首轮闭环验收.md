## 1. 任务目标与交付边界

本次整理只完善文档，没有创建前端工程、安装依赖、启动服务或执行数据库操作。任务仍为待开始。正式实施由用户独立开发和验收，实际执行者、日期和证据按真实结果填写，不设置成员A/B签字。

| 范围 | 本任务交付 | 边界 |
|---|---|---|
| 网页 | 登录、列表、详情、控制面板、命令结果 | 中文浅色桌面界面；主要尺寸1440×900，兼容1280×720；不要求手机布局 |

## 3. 页面、布局与角色设计

### 3.1 页面组成

桌面采用顶部账号/连接状态栏、授权箱体导航和主要内容区。详情通过卡片分组，控制与结果独立成区；小尺寸桌面允许页面纵向滚动，关键操作不能被遮挡。状态除颜色外必须有文字，表单有标签、单位、键盘焦点及错误提示。

| 页面或区域 | 路由或位置 | 内容与动作 | 异常与空状态 |
|---|---|---|---|
| 登录 | `/login` | 账号、密码、提交中、统一失败提示 | 不保存密码；登录失败不泄露账号存在性；不显示角色选择 |
| 箱体列表 | `/boxes` | 已授权箱体标识、连接完整性、关键摘要、MOCK、最后同步时间 | loading、empty、error、ready独立；无授权不等于无设备故障 |
| 箱体详情 | `/boxes/:boxId` | 环境、姿态、定位坐标、节点、质量、门、告警及允许的哨兵状态 | 按角色省略禁止区域；未加载、无样本、无效值、未知判断各有说明 |
| 控制面板 | 详情内 | 五类命令表单、目标选择、参数校验、操作确认 | 根据角色和能力显示；无合适目标、未校时或离线给出实际原因，服务端最终决定 |
| 命令结果 | 详情内，按操作号查看 | 整体终态、逐节点结果、实际状态、迟到事实、刷新 | 不提供无契约支持的全量命令历史；无操作与查询失败分开 |
| 全局状态栏 | 登录后布局 | 当前账号、角色、退出、WS连接状态、最后同步时间 | WS中断不能冒充设备离线；退出清理所有敏感状态 |

门在尚无融合判断时显示“未知／证据不足”（UNKNOWN/INSUFFICIENT）。告警assessment=UNKNOWN时显示“尚未完成判断”，active与level的null不转换为“无告警”。外卖用户看到结论区域不代表已有结论；空结论不能解释为从未开门。定位只展示坐标与MOCK，不做未经核对的地图坐标转换。

### 3.2 角色矩阵

| 服务端角色 | 首轮可见内容 | 控制和结果 |
|---|---|---|
| LOGISTICS_VIEWER（物流寄收件人） | 授权箱体、允许的监测及节点诊断 | 无控制入口，不展示操作者专属结果 |
| LOGISTICS_OPERATOR（物流操作者） | 授权业务数据及诊断 | 五类允许命令及结果 |
| DELIVERY_USER（外卖用户） | 允许的环境、MOCK定位、融合结论及相关告警 | 无控制和命令结果；省略姿态、证据、诊断、哨兵操作明细 |
| COURIER（骑手） | 授权业务数据及允许的诊断 | 仅布撤防及其允许的结果，不提供其他配置控制 |

登录后以`/me`返回的当前身份与授权为准，不接受浏览器自选角色。DELIVERY_USER不请求节点诊断，不订阅node_status或command_status。权限变化、403及账号切换时，清理受影响的数据、订阅与命令表单；不能只是隐藏仍存有敏感内容的组件。

## 4. 计划工程与公共能力

以下是正式实施时的目录职责，本轮不创建占位目录或文件：

```text
frontend/
├─ src/
│  ├─ app/          # 入口、布局、全局初始化
│  ├─ router/       # 路由、登录守卫
│  ├─ api/          # HTTP、契约类型、错误转换、命令适配
│  ├─ stores/       # 身份、箱体、连接、命令状态
│  ├─ features/     # 登录、列表、详情、控制、结果
│  ├─ components/   # 状态、时间、质量标记等复用组件
│  └─ realtime/     # WS生命周期、订阅、重同步
└─ tests/           # 单元、组件、浏览器验证
```

调用关系为“页面组件 → store/业务动作 → HTTP或WS适配 → 服务端”；组件不各自拼接报文和维护连接。DTO只依据允许的响应字段，不把设备原始JSON直接展开渲染。响应中的uint64等大整数不得经JavaScript Number静默丢失精度；S1核对实际字段，按无损解析/字符串展示处理，不能修改报文字段类型规避问题。

| 公共能力 | 输入与输出 | 约束 |
|---|---|---|
| HTTP适配 | 路径、请求、内存Token → 契约DTO或分类错误 | 统一Bearer与request_id；凭据不进日志；支持取消过时查询 |
| 身份store | login/me → 当前身份、授权范围 | Token仅内存；刷新重新登录；退出关闭连接、清空缓存和待确认表单 |
| 箱体store | 授权列表、详情快照 → 页面数据与加载状态 | 按箱体及当前会话隔离；请求代次校验防止旧响应覆盖 |
| 实时管理器 | 当前会话、订阅箱体 → 消息、连接状态、重同步请求 | 一个会话一个受控连接；离开页面取消订阅；会话结束停止重连 |
| 命令store | 用户确认的固定请求与幂等键 → 操作和节点事实 | 网络不确定时保留同键同内容；不能自动新建操作 |

开发端口5173、后端回环8080；Vite代理`/api`与`/ws`到现有后端，保留浏览器Origin供服务端校验。端口被占用不静默切到未授权来源；预览或自动化也使用明确允许的Origin。公开前端配置只含地址等非秘密信息，不能放数据库密码、Broker凭据或JWT签名密钥。

## 5. HTTP接口与异常约定

HTTP前缀为`/api/v1`，具体请求/响应及限制引用当前有效契约，不另建一套业务字段规范。

| 页面/动作 | 接口 | 角色与字段消费 | 异常处理 |
|---|---|---|---|
| 登录 | POST `/auth/login` | 所有现行业务账号；读取Token及到期信息 | 统一凭据失败；依赖故障不冒充密码错误 |
| 当前身份 | GET `/me` | 已认证用户；账号、角色、授权箱体 | 401结束会话；加载完成前不按默认角色显示敏感区域 |
| 箱体列表 | GET `/boxes` | 仅授权箱体；按实际快照结构适配 | 空授权、网络失败分开，不假定存在名称等未定义字段 |
| 详情 | GET `/boxes/{id}/latest` | 角色投影后的快照、质量、结论 | 403清除缓存；404显示不存在；不能回退到其他箱体数据 |
| 节点区 | GET `/boxes/{id}/nodes` | 仅有诊断权限角色；无接入记录保持可空时间 | 外卖用户不调用；无数据不能伪造在线或启动标识 |
| 控制 | POST `/boxes/{id}/commands` | 角色允许的命令；Idempotency-Key | 202仅受理；409明确冲突，不自动换键重试 |
| 结果 | GET `/boxes/{id}/commands/{operation_id}` | 按角色和操作类型查看整体、节点及实际事实 | 无权或不存在清理对应结果；网络错误不推断执行失败 |
| WS准备 | POST `/ws-ticket` | 当前会话的一次性ticket与有效期 | 失败保持REST可用，按错误类别决定是否重连 |
| 后续接口 | GET事件、轨迹、CSV三个既有操作 | 登记当前契约及TASK-010消费位置 | 本任务不建立完整查询/导出页面 |

401清除敏感状态并返回登录；403显示无权并移除受影响数据；404显示资源不存在。网络错误与503标记暂不可用，旧数据可保留但必须标注最后同步时间和非实时状态。登录本身的401留在登录页，不造成循环跳转。

普通查询提供重试，不无限并发；控制请求超时不自动以新键重发。错误提示使用脱敏信息和request_id，不显示堆栈、SQL、完整Token或ticket。任何设备/用户文本按普通文本渲染，不用原始HTML插入。

## 6. 实时状态、时间和恢复

首次REST读取后连接WS；订阅建立或恢复后再次REST读取，消除连接间隙。重同步时暂存当前订阅消息，完成后重新收敛；使用会话/箱体请求代次和契约中可比较的版本依据防旧响应覆盖，无可靠顺序依据时重新读取，不按到达顺序盲目覆盖。

| 状态维度 | 显示与更新依据 | 禁止推断 |
|---|---|---|
| 网页连接 | HTTP结果、WS连接及最后同步时间 | WS断开不能说明节点已离线 |
| 节点连接 | 服务端当前代次、LWT及90秒无活动判断 | 浏览器不得另建一套权威在线状态 |
| 箱体连接完整性 | 必需节点的服务端聚合 | 单节点在线不能显示双节点完整在线 |
| 数据新鲜度 | 服务端质量及观测年龄；环境/姿态5秒、定位15秒 | 心跳和重复携带旧位置不能刷新采样时间 |
| 有效性与时间质量 | valid、UNSYNCED及可空原UTC等契约字段 | 缺值不填0；接收时间不冒充设备发生时间 |
| 门、告警、哨兵 | 独立业务维度及真实结果 | 未判断不显示正常；操作受理不等于ARMED |

缺少位置观测标记时保持freshness=UNKNOWN、stale=true。页面定时刷新只能使旧数据趋于过期，不能制造新鲜；断线后禁止持续以绿色实时样式显示旧值。5秒/15秒临界判断沿用服务端实现，页面不另行改定阈值比较语义。

WS使用30秒一次性ticket、既有订阅/取消订阅结构及服务端投影。重连重新申请ticket，退避从1秒递增至最多30秒并加小幅抖动；成功订阅后复位，退出/401时停止。混合越权整次拒绝；撤权后清理受影响状态并重新获取身份与授权，恢复前不推送旧缓存。

浏览器自动处理协议Ping/Pong，不新增JSON心跳。服务端message_id不能替代稳定业务ID去重。没有生产者的alarm等消息不制造样例冒充运行结果。WS为尽力通知，不承诺可靠重放；终态后的迟到事实可通过允许的推送、手动刷新和重连补查取得。

## 7. 控制表单、幂等与结果

| 命令 | 可操作角色/目标 | 参数及校验来源 | 模拟结果和边界 |
|---|---|---|---|
| sentry | 物流操作者、骑手；服务端选定必需节点 | on、duration_s为0～86400；真实修订号由服务端分配 | 3秒缓冲与ARMED分别显示；duration_s从ARMED起算，0不自动到期 |
| output | 物流操作者；角色支持的ENV/POSE输出 | kind=light/fan/indicator、on、duration_s=1～30；能力由服务端校验 | 仅模拟输出与按期限关闭，不表示真实灯/风扇动作 |
| gps_mode | 物流操作者；支持定位节点 | FIXED/ROUTE/WALK及uint32 seed | 模拟定位，始终标记MOCK |
| profile | 物流操作者；支持画像节点 | profile_id、温湿上下限及正回差；单位、范围、相互关系沿用需求与契约 | 请求值与已采用配置分开；真实采用后才更新显示，不声称告警算法已实现 |
| calibrate | 物流操作者；支持校准节点 | params为空对象；提交前确认 | 显示模拟校准，不声称真实校准成功 |

目前SentryParams要求sentry_revision，HTTP适配层提交合法占位值1以满足当前结构；不向用户暴露编辑项。服务端忽略客户端修订值并在事务内分配真实修订号，页面只消费返回事实。S1对照现有CommandService和有效Schema再次核对该行为；若不一致，登记接口缺口，不让浏览器自行生成真实业务修订。

一次用户确认产生固定请求及一个不超过64字节的幂等键。提交期间禁用重复按钮；响应丢失后保留原键与原内容，提示结果待确认，允许同键重试。修改参数并再次确认才是新操作；账号切换清理原请求，不跨用户复用。该缓存仅在当前会话内，刷新会结束会话，不能据此承诺刷新后的自动恢复。

202显示已受理及operation_id，不显示已执行。允许角色通过WS和每2秒一次、同一时刻最多一个在途请求补查结果；终态停止常规轮询，失败时保留可手动刷新入口。离开箱体/退出时取消请求与定时器。

| 服务端结果 | 页面含义 |
|---|---|
| PENDING等非终态 | 等待或处理中，显示逐节点事实，不先行修改为成功 |
| SUCCEEDED | 全部目标满足服务端成功口径；仍注明模拟执行范围 |
| PARTIAL | 部分成功，列出未成功或未完成节点；不得显示整体已布防 |
| FAILED | 服务端确认失败；给出允许的脱敏原因 |
| EXPIRED | 整体等待期限已到，不能解释为设备一定未执行 |

布撤防10秒操作截止、命令15秒有效期保持；其他命令沿用原15秒有效期。整体终态固定；迟到执行事实与当前实际状态独立展示，不自动撤销动作或把终态改成功。只有必需节点实际确认满足时才能显示整体ARMED；缺少可靠剩余期限时不伪造准确倒计时。
