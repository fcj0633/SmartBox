## 工作内容（首轮 DEMO 切片）

**目标：骑手可以真实完成“选箱 → 填写物品 → 开始 → 结束 → 查看历史”。**

- 独立 `transport_tasks` 表即可保存任务、运输编号、箱体、操作者、物品摘要、READY/ACTIVE/COMPLETED 及起止时间。
- 利用 MySQL 生成列唯一索引或等效简单约束保证同箱最多一项 ACTIVE；保留服务端身份/使用权检查，不依赖按钮禁用。
- 开始时重新核验箱体使用权与当前在线状态；环境异常时展示明确警告，不承诺物品安全；结束后固定结束时间。
- 简单重复点击返回已完成状态或明确冲突即可；不设计完整通用幂等中间件、分布式任务调度、操作重试队列。
- ACTIVE 期间禁止普通收回分配；首轮**不做紧急撤权接管流程**，对应候选 REQ-M07-007 的高阶场景延后。

## 推荐实现顺序

1. 按 [演示优先方案](../guides/CR-006-演示优先实施方案.md) 实现单任务表和必要唯一索引；仅追加 Flyway 迁移。
2. 新增创建准备、保存物品、开始、结束、本人任务列表和详情这几个 API。
3. 后端执行状态转换与事务；完成后按任务范围查询历史，不覆盖旧任务。
4. 用真实 MySQL 演示主流程及同箱两次开始拒绝；不安排 20 并发压测与全量失败矩阵。
5. 留存简单的测试输出与已知未覆盖范围，不虚构生产级幂等/可靠性。

## 验收与不做什么

首轮 [TC-014](../../testing/cases/TC-014-运输事务与幂等并发.md) 完成少量主路径与冲突检查即可；严格 20 并发、紧急企业接管、灾难恢复与完整操作审计仍属未来增强，不计当前 DEMO 已验收。
