# SmartBox 开发者完整部署指南

本指南面向第一次取得仓库的开发者。采用 Windows 开发、运行服务与烧录，Ubuntu 编译固件的组合。软件模拟闭环无需开发板；真实双板模式需要 Nano＋IA1、Nano＋SC2 和同一可互访的 2.4GHz 网络。当前能力与边界见[根导读](../../../README.md)，核心固件阅读见[固件导读](../../../firmware/README.md)。

## 1. 交付内容与完整性的含义

仓库包含本项目的固件 C 源码、后端 Java、网页 Vue、Python 模拟器、配置模板、协议、数据库迁移和测试工具。第三方 OpenHarmony 框架、海思预编译库、GN/Ninja 与 RISC-V 工具链通过独立 SDK 包提供，不将它们混入 Git。

仅克隆 Git 仓库不会自动取得 SDK。请向交付方取得本指南所述校验包；不要把上游当前 master 直接当成本项目已验证快照。

交付目录包含 `SmartBox-source.zip`、`source.json`、`sdk.tar.gz`、`toolchains.tar.gz`、`bundle.json` 和 `START-HERE.md`。`source.json` 记录源码提交号与压缩包 SHA256；zip 内的 `SOURCE.json` 保存来源提交和文件哈希，无 .git 也可追溯固件构建，修改后会记录偏差，不借用父目录的 Git 仓库。`bundle.json` 记录 SDK/工具链逐文件内容、权限、链接、分发调整、组件许可证位置和压缩包校验值。源码包由提交树导出，不包含本机 secrets、私钥、数据库、缓存、日志或生成固件配置。

当前 SDK 无上游 Git 元数据，交付标注为本地验证的派生快照，不能声称对应某个上游提交。官方仓库地址仅说明来源。SDK 包清除个人 `study_*`、SmartBox 构建副本、旧输出及示例网络凭据，并选择一个实际存在的官方线程例程作为默认入口；调整记录在清单中，原 SDK 不受修改。

**许可证边界：**保留 SDK、厂商组件、编译器和第三方组件各自的许可证；根 Apache 许可证不能替代所有组件条款。包用于本地开发交接，公开再分发前仍需核验厂商二进制分发条款和工具链对应源码提供义务。本包不包含整台虚拟机，也不保证 Windows 安装包、Maven/npm/pip 依赖完全离线可用。

“代码完整”指已交付功能的开发源代码及依赖接入路径完整。完整姿态/门融合/告警/哨兵算法、Flash 事件可靠性和完整历史页面仍分别属于 TASK-008～010，不能通过部署成功将其视为实现。

## 2. Windows 前提与工具安装

使用 Git 检出仓库，或解压源码包到专属目录。允许中文和空格；不要放在 SDK 内，也不要在同步网盘同时运行两个工作副本。以下命令均在 PowerShell 的仓库根目录执行，示例中的地址和目录必须换成自己的值。

| 工具 | 已验证基线 | 安装后检查 | 用途 |
|---|---|---|---|
| Python | 3.10.8 | `python --version` | Windows 工具与契约测试 |
| Java | 21.0.10 | `java -version` | 后端编译与运行 |
| Maven | 3.9.14 | `mvn -version` | 解析锁定后端依赖 |
| Node / npm | 24.14.0 / 11.9.0 | `node --version`、`npm --version` | 网页构建 |
| MySQL | 8.0.44 | `mysql --version` | 本机真实数据库 |
| Mosquitto | 2.0.14 | 安装目录中运行 `mosquitto -h` | 项目 Broker |
| OpenSSH 客户端 | Windows 可用版本 | `ssh -V` | Ubuntu 执行与传输 |
| HiBurn / CH340 | 与 Nano 配套 | 设备管理器检查 COM | 仅真实板烧录 |

安装来源：[Python](https://www.python.org/downloads/)、[OpenJDK](https://jdk.java.net/archive/)、[Maven](https://archive.apache.org/dist/maven/maven-3/)、[Node](https://nodejs.org/download/release/)、[MySQL](https://downloads.mysql.com/archives/community/)、[Mosquitto](https://mosquitto.org/download/)。精确业务依赖依据[版本矩阵](../../development/environment/工具与依赖版本矩阵.md)和工程锁文件，不因安装工具时看到新版本而自动升级。

`JAVA_HOME` 指向 JDK 根目录，PATH 包含 Java、Maven、Node、MySQL 客户端和 SSH。不要使用 Oracle 的占位 Java 启动器。Mosquitto 2.0.14 的 Windows 路径兼容由新工具使用相对文件引用和明确工作目录处理，不依赖 8.3 短文件名；旧配置保留原方式。

Mosquitto 默认发现 `C:\Program Files\mosquitto\mosquitto.exe` 或 PATH；非默认安装可通过模拟器配置准备函数的 `executable` 参数指定，见[模拟器导读](../../../tools/simulator/README.md)。原 Windows Mosquitto 服务保持停止，项目另起专属进程。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r tools/requirements-contracts.txt
.venv\Scripts\python.exe -m pip install -r tools/requirements-simulator.txt
.venv\Scripts\python.exe tools/frontend.py install
```

这只安装项目虚拟环境和 `frontend/node_modules`，网页安装还准备匹配版本的 Chromium，首次需要网络。不要复制别人的 `.venv`、`node_modules` 或系统安装目录。后续统一使用 `.venv\Scripts\python.exe`；已经有虚拟环境时可用 `tools/project.py install-deps` 复现上述安装。

## 3. Ubuntu 与 SSH：不需要映射盘

Ubuntu 已验证基线为 18.04、Python 3.8.0、宿主 GCC 7.5.0、SCons 3.0.1。交付 GN 1523、Ninja 1.9.0 和 RISC-V GCC 7.3.0/链接器 2.31.1。SCons、Python 和宿主系统库仍由 Ubuntu 环境提供；不复制整台虚拟机或升级系统 Python。

在 Ubuntu 中确认 `python3 --version`、`python --version`、`gcc --version`、`scons --version`。官方旧构建脚本使用 `python`；它也必须指向已验证的 Python 3 环境。若现有环境不满足，先依据[环境说明](../../development/environment/环境清单.md)修复，不通过改脚本绕过。

Windows 使用自己的 SSH 会话，MobaXterm 标签页与磁盘映射都不是执行通道。首次开发者生成自己的密钥，并将 **`.pub` 完整公钥行**加入 Ubuntu `~/.ssh/authorized_keys`，不要把 `SHA256:...` 指纹当公钥。私钥不放进仓库。Ubuntu `.ssh` 权限 700，authorized_keys 权限 600。

首次交互连接时通过虚拟机控制台核对主机指纹，确认后再做严格检查：

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519_smartbox" -o IdentitiesOnly=yes -o BatchMode=yes -o StrictHostKeyChecking=yes bearpi@YOUR_UBUNTU_IP "whoami"
```

输出应是目标用户。验证失败时先处理 IP、sshd、公钥、权限和已知主机记录；不关闭主机指纹校验，不复制原开发者的私钥。磁盘映射可继续用于浏览，但新的 `project.py firmware-build` 默认只通过 SSH 同步和执行。

## 4. 校验、安装 SDK 与工具链

先保存完整交付目录，校验接收的 `source.json` 与 `bundle.json`。没有可信渠道取得的清单时，单独校验压缩包无法证明来源。Windows 可用 `Get-FileHash -Algorithm SHA256` 对照发送方校验值。

准备本地配置（下一章解释每个文件）：

```powershell
.venv\Scripts\python.exe tools/project.py init
```

编辑忽略文件 `secrets/workspace.local.json`，先填写实际 SSH 主机、账户、外部私钥路径。随后安装到 Ubuntu 中**尚不存在**的专属目录，例如 `/home/bearpi/smartbox-sdk`：

```powershell
.venv\Scripts\python.exe tools/sdk_bundle.py verify --bundle artifacts/received-sdk
.venv\Scripts\python.exe tools/sdk_bundle.py install --bundle artifacts/received-sdk --destination /home/bearpi/smartbox-sdk
```

安装会上传到独立临时目录，核验两个压缩包、拒绝路径越界和危险链接，按 Unix 权限解压，再逐文件核验哈希、权限和链接。目标存在时拒绝合并，不覆盖学习 SDK。失败保留现场用于定位，不能把未验证的目录拿去构建。首次安装需预留 SDK、工具链、上传副本和后续构建备份空间，建议 Ubuntu 至少 8GB 可用。

安装后目录：

```text
/home/bearpi/smartbox-sdk/
├─ sdk/                 # build.py、framework、vendor、官方示例
├─ toolchains/
│  ├─ gn/
│  ├─ ninja/
│  └─ gcc_riscv32/bin/
└─ installed-bundle.json
```

将 workspace 的 `ubuntu.sdk` 指向这里的 `sdk`，`tool_paths` 按 GN、Ninja、GCC-bin 顺序填写三个绝对目录。工具路径只加入本次构建进程，不改 `.bashrc`。不要直接在 Windows 解压再复制 Linux 工具链，这会丢失执行权限或链接语义。

## 5. 本地配置与凭据

| 文件 | 内容 | 生成或填写方式 | 重跑与迁移注意 |
|---|---|---|---|
| `secrets/workspace.local.json` | SSH、SDK、工具路径 | init 生成占位，开发者填写 | 不含私钥正文；外部路径需本机调整 |
| `secrets/backend.local.json` | dev/test 数据库账号、JWT、初始化引用 | init 随机生成 | 既有文件不重置；移动仓库时相对 bootstrap 路径仍可用 |
| `secrets/backend-*.bootstrap.local.json` | 四角色演示账号和授权 | init 随机生成 | 本地查看账号密码，不发送聊天、不截图 |
| `secrets/database-provision.local.json` | 首次建库对象归属记录 | db-init 生成 | 不可随意删除，否则既有库会被视为外来对象 |
| `secrets/development-init.pending.local.json` | 中断时保留的初始化凭据 | 首次 init 暂存，成功后移除 | 重跑复用已预留值；内容冲突则拒绝覆盖 |
| `secrets/mqtt.local.json` 及对应目录 | 账号、ACL、配置、模拟代次 | init 调用 prepare | 包含本机运行路径；搬迁前检查，不自动重建身份 |
| `secrets/firmware.local.json` | Wi-Fi、Broker LAN 地址与校时服务器 | 按硬件指南填写 | 仅接真实板需要 |
| `secrets/hardware/` | 区间账本、硬件 Broker 配置 | hardware prepare | 严禁丢弃区间账本后重新分配 |
| `firmware/include/sb_local_config.h` | 本地固件编译网络及代次参数 | hardware prepare | Git 忽略；不能随源码交付 |

workspace 示例只表示结构，所有值需按实际填写：

```json
{
  "format": 1,
  "ubuntu": {
    "host": "YOUR_UBUNTU_IP", "user": "bearpi", "port": 22,
    "key": "C:/Users/YOUR_USER/.ssh/id_ed25519_smartbox",
    "sdk": "/home/bearpi/smartbox-sdk/sdk",
    "tool_paths": ["/home/bearpi/smartbox-sdk/toolchains/gn", "/home/bearpi/smartbox-sdk/toolchains/ninja", "/home/bearpi/smartbox-sdk/toolchains/gcc_riscv32/bin"]
  }
}
```

`init` 对已存在 backend/MQTT 配置只保留、检查，不覆盖密码、JWT 或代次；首次初始化有未完成记录时重跑会继续写入缺失文件，并复用同一批秘密，遇到内容冲突则失败。没有未完成记录却缺少初始化文件时需人工核对，不用删除 secrets 解决。旧开发目录迁移时，MQTT 的绝对路径、硬件 Broker 地址和工具路径必须明确调整并核对配置模板，避免静默迁移后误连旧数据。只有首次全新环境才执行首次初始化流程。

```powershell
.venv\Scripts\python.exe tools/project.py doctor
```

doctor 只读报告依赖是否存在、配置文件是否存在、占用端口、SSH SDK 路径和空间。它不是完整兼容性认证；版本仍需核对表格，数据库连通性通过后续初始化和健康检查验证。

## 6. 首次建库、迁移与演示账号

MySQL 服务由开发者正常安装并保持运行。项目不会停止共享服务。默认使用本机 TCP 3306；独立演练实例可在首次 init 时指定 `--mysql-port 13306`。数据库名与账号仍限定本项目，不允许借此连接其他库。

```powershell
.venv\Scripts\python.exe tools/project.py db-init
.venv\Scripts\python.exe tools/backend.py build
.venv\Scripts\python.exe tools/backend.py bootstrap
```

db-init 在隐藏输入中读取本机 root 密码，仅在子进程环境使用，不保存到应用、参数或受控文件。创建 `smartbox_dev`、`smartbox_test`，各配迁移账号和读写账号；运行账号没有 DDL 权限。结构由后续 Flyway 执行 V1～V9，演示数据由显式 bootstrap 事务写入。不会把 root 当运行账号。

MySQL DDL 不保证整个初始化原子回滚，工具用绑定端口及服务端 UUID 的本地归属记录记录已创建对象。中断后重跑只继续已确认属于本次初始化的对象；如果恰好在服务端创建和记录之间中断，下一次会拒绝，需人工核对后恢复记录，不能自动接管同名账号。已有项目库但没有归属记录时也拒绝；原开发者直接复用既有配置，不要执行 db-init 接管。

空库第一次启动应成功迁移；第二次启动 Flyway 校验不重建数据。迁移校验失败时保留错误和数据库，不运行自动 clean/repair、不改 V1～V9 旧文件。初始化重跑不重置密码、不覆盖授权；冲突导致初始化事务回滚。测试库清理必须同时显式选择 test 与清理同意，不能用开发库替代。

生产安全加固、HTTPS、托管数据库备份和公网账号轮换不属于本地开发部署。

## 7. 启动软件模拟闭环

```powershell
.venv\Scripts\python.exe tools/frontend.py build
.venv\Scripts\python.exe tools/project.py start --mode simulator
```

前台管理器按 Broker→后端→ENV/POSE 独立进程→网页启动。另一个 PowerShell 可执行：

```powershell
.venv\Scripts\python.exe tools/project.py status
.venv\Scripts\python.exe tools/project.py stop
```

也可在启动窗口按 Ctrl+C。只停止本轮创建的子进程，通过 PID 创建时间确认管理器身份；端口被其他服务占用时拒绝，不结束别人进程。强制终止管理器或电脑重启留下记录时，先核对记录中的子进程、端口和日志，再执行 `tools/project.py recover-state` 归档过期记录；有已登记进程或端口活动时会拒绝，不直接按旧 PID 结束进程。

打开 `http://127.0.0.1:5173`，使用本地 dev bootstrap 中的演示账号。应看到授权箱体和两个模拟节点；GPS 标注 MOCK，门与告警可能是未知，不等于正常或安全。物流操作者可执行五类模拟命令，控制后检查操作号、逐节点结果和模拟状态。事件确认必须由后端事务提交后生成，PUBACK 不代表保存。

如已有真实板代次写入开发库，新的低代次模拟状态不能覆盖它。先停止同身份真实板，并使用明确隔离的测试配置和测试库验收；不得清空服务端历史或随意倒退代次来制造成功。

## 8. 固件同步、构建、归档与恢复

先按[真实板启动指南](../../development/guides/编译烧录与联调流程.md)准备 firmware 本地配置和区间账本。缺少私有头文件时真实构建应失败，不能用受控源码内置默认密码绕过。

```powershell
.venv\Scripts\python.exe tools/hardware.py check
.venv\Scripts\python.exe tools/hardware.py prepare
.venv\Scripts\python.exe tools/project.py firmware-build
```

`prepare` 会预留新 boot 区间，不应每次启动 Broker 都执行。相同镜像只能在其已分配范围内启动；保留区间账本，不能因串口测试重新把代次设为零。

SSH 构建流程：上传临时源码输入→受控差异预览→备份 sample 入口、旧产品输出和厂商构建状态→ENV 同步/编译/链接/立即归档→POSE 同步/编译/链接/立即归档→恢复原入口及输出。SDK `sample/logistics_box` 是受控副本，日常修改始终在仓库 firmware。

构建使用 Ubuntu 现有 `python build.py BearPi-HM_Nano`。每个角色必须有独立日志、`libsmartbox.a`、最终映射、带身份的链接对象和 allinone 镜像校验值。网络、编译、链接、烧录、运行是不同证据；两份同一 bin 改名不算双角色构建。

传统映射方式 `tools/build_firmware.py --sdk-root ... --remote-sdk ...` 继续可用；新入口显式选择 SSH transport，路径不依赖 Z:。异常时保留本地 `run.json` 和 Ubuntu 备份工作目录，不删除锁；同一次恢复必须传原连接、SDK、transport 和 `--recover` 目录。发现并发修改时停止恢复并人工核对，不能覆盖新变化。

## 9. Windows 烧录与串口

断电安装扩展板，先只连 ENV＋IA1，确认新增 COM。选择对应角色归档的 `Hi3861_wifiiot_app_allinone.bin`，核对 SHA256；不要拿旧 SDK 恢复输出或其他角色文件烧录。文件路径建议使用短 ASCII 路径，避免 HiBurn 对中文或过长路径的兼容问题。

按[官方入门流程](https://www.bearpi.cn/dev_board/bearpi/hm/nano/software_OpenHarmony/BearPi-HM_Nano%E5%8D%81%E5%88%86%E9%92%9F%E4%B8%8A%E6%89%8B.html)选择串口与镜像、Auto burn、连接，然后物理 RESET 进入下载；看到 Execution Successful 后断开 HiBurn、释放串口，再复位正常启动。调试日志使用 115200；烧录速度与工具设置依据配套流程。一直准备时先核对端口归属、虚拟机 USB 抢占、镜像完整性和复位时机，不反复改业务代码。

日志应能确认角色和身份，再对 POSE＋SC2 重复。不能只凭编译成功确认扩展板安装或输出动作。物理灯/风扇观察需操作者确认，勿触碰风扇叶片。

## 10. 接入真实双板

电脑和开发板处于可互访的 2.4GHz WPA2 网络；无 AP 隔离。板端 Broker 必须是电脑实际 LAN 地址，不是 127.0.0.1。硬件 Broker 显式监听指定网卡并保留本机服务路径，后端 8080、网页 5173 仍只回环监听。

```powershell
.venv\Scripts\python.exe tools/project.py start --mode hardware
```

硬件模式不会启动模拟节点，不自动 prepare、不自动烧录或改防火墙。若 Windows 防火墙阻止板端连接，只添加项目 Mosquitto 程序、TCP1883、当前网络类型及受控来源子网的规则，记录规则名，结束后恢复；不要整体关闭防火墙。

真实固件本期只执行 output。补光、风扇、SC2 指示灯分别验证动作与自动关闭，其他四类按钮不代表真实固件已经支持。校时失败仍可上报但控制按契约拒绝；不能用主机模拟确认替代真实执行。

## 11. 排错与验证入口

| 现象 | 优先核对 | 不能采用的处理 |
|---|---|---|
| doctor 缺工具 | PATH、JAVA_HOME、工具版本及安装目录 | 自动升级整个系统 |
| SSH 超时/认证失败 | 虚拟机 IP、sshd、公钥、主机指纹 | 关闭严格主机检查 |
| SDK 解压失败 | 可信清单、SHA256、空间、目标不存在、权限 | 合并覆盖已有 SDK |
| 数据库拒绝 | 本机端口、账号对应库、归属记录、Flyway错误 | 用 root 运行应用或 clean 开发库 |
| 网页无法访问 | 5173/8080 日志、代理、健康检查 | 将未知数据改为正常 |
| Windows Java 启动报内部选择器错误 | 先确认本机 AF_UNIX 支持，再决定本地配置 `SMARTBOX_WINDOWS_TCP_SELECTOR=true` | 所有电脑无条件应用此兼容项 |
| 板端不上线 | LAN 地址、2.4GHz、WPA2、AP隔离、ACL、同身份模拟器 | 开放匿名连接或全方向 ACL |
| 控制被拒绝 | 时间质量、权限、目标能力、有效期及实际支持命令 | 伪造成功回执 |
| 旧位置/节点状态 | 观测标记、boot、序号、新鲜度 | 用心跳刷新采样时间 |
| 退出后占用端口 | 本次进程日志、管理器身份与子进程 | 杀死全部 Java/Python/MySQL |

只读/单元检查：

```powershell
.venv\Scripts\python.exe tools/project.py check
.venv\Scripts\python.exe tools/backend.py unit
.venv\Scripts\python.exe tools/frontend.py check
.venv\Scripts\python.exe tools/mqtt.py unit
git diff --check
```

真实数据库集成与浏览器验收会重置专属测试库，必须显式同意：

```powershell
.venv\Scripts\python.exe tools/backend.py test --profile test --allow-test-reset
.venv\Scripts\python.exe tools/frontend.py integration --profile test --allow-test-reset --run-dir artifacts/my-new-browser-run
```

新 evidence 目录必须尚不存在；缺依赖/配置时失败，不静默跳过。完整验收另见[测试地图](../../../tests/README.md)，不能把这些检查替代真实板、24小时稳定性或Flash掉电验收。

## 12. 迁移与交接

源码用 Git/源码包交接；SDK 用清单和独立压缩包交接；本机密码、私钥、账号授权和硬件区间账本不能放入公开包。需要继续同一批板件时，通过私密渠道交接相应配置与账本，先核对数据库最高代次，不重新从零分配。

部署复验报告至少包含源码提交、SDK清单哈希、实际工具版本、迁移结果、两角色构建与恢复、软件闭环、端口与进程清理、未验证项目。项目默认不会自动打标签或推送 Git。已有应用迁移、冻结协议和历史报告不得为了部署方便而修改。

工具实现入口：[统一工具](../../../tools/project.py)、[首次配置与建库](../../../tools/development_config.py)、[SDK交付](../../../tools/sdk_bundle.py)、[SSH同步](../../../tools/firmware_ssh.py)。文档和源码共同维护；先检查输入，再做有写入影响的操作。

维护者重新生成交付包时，先核对 workspace 指向已验证 SDK 和三个工具目录，再执行：

```powershell
.venv\Scripts\python.exe tools/sdk_bundle.py export --bundle artifacts/sdk-handoff --destination /home/bearpi/smartbox-export-UNIQUE
.venv\Scripts\python.exe tools/sdk_bundle.py verify --bundle artifacts/sdk-handoff
```

两个目标均须是新目录。检查分发调整、隐私扫描、许可证和新安装编译结果后，先提交本轮源代码，工作区清洁时执行：

```powershell
.venv\Scripts\python.exe tools/project.py package --bundle artifacts/sdk-handoff
```

该操作从当前提交导出源码，不递归打包工作目录，也不会自动发布 SDK。交付发送方通过可信渠道另行提供 `source.json`、`bundle.json` 和压缩包 SHA256。SDK 包中有一份上游空的总声明文件；组件声明需依据实际非空文件核对，不能用文件数量推断条款审核已完成。
