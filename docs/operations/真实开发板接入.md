# 真实开发板接入

## 结论

前后端启动后**不能直接连接开发板**。浏览器不直连设备，后端也不是设备发现服务。

真实链路：

```text
浏览器 -> 前端 -> 后端 -> 远程 MQTT Broker -> 开发板
```

当前唯一支持的 Broker：

```text
z789ffe0.ala.cn-hangzhou.emqxsl.cn
TLS 8883
```

## 后端 MQTT 配置

默认关闭：

```text
SMARTBOX_MQTT_ENABLED=false
```

启用真实接入时：

```text
SMARTBOX_MQTT_ENABLED=true
SMARTBOX_MQTT_URL=ssl://z789ffe0.ala.cn-hangzhou.emqxsl.cn:8883
SMARTBOX_MQTT_USER=smartbox_backend
SMARTBOX_MQTT_PASSWORD=<从本地 secrets 提供，不提交>
SMARTBOX_MQTT_CA_FILE=<远程 CA 文件绝对路径>
```

约束：

- 只接受 `ssl://` DNS 域名 + 8883；
- 纯 IP、`tcp://`、非 8883、本地 `127.0.0.1:1883` 一律启动失败；
- 没有本地 Broker 回退；
- 缺少 CA 或账号配置时启动失败；
- 后端不提供 Broker、账号创建、ACL 或证书轮换。

## 当前 main 的能力边界

main 只保留后端 MQTT 客户端代码，**不提供**：

- Broker 部署配置；
- SDK、交叉编译、烧录工具；
- 模拟器；
- 硬件联调脚本；
- 真实板验收。

`firmware/` 仅作为源码参考。需要完整硬件工具时使用完整开发树 `SmartBox-full`，而不是 main。

## 最小判断方法

- `SMARTBOX_MQTT_ENABLED=false`：只能看到 `DemoFleetService` 的模拟数据；
- 启用后：后端只尝试连接远程 TLS Broker，不尝试本地地址；
- Broker 不可达/账号错误：后端不会自动发现板子，设备数据不会出现；
- 前端启动成功、页面能打开，不代表开发板已连接。

远程账号和 CA 由本地 `secrets/mqtt.cloud.local.json` 提供，不进入 Git。
