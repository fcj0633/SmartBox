# 真实开发板接入

## 结论

前后端启动后**不能直接连接开发板**。浏览器不直连设备，后端也不是设备发现服务。

真实链路：

```text
浏览器 -> 前端 -> 后端 -> MQTT Broker -> 开发板
```

缺任何一项都只能使用模拟数据：

- 可访问的 MQTT Broker；
- 已烧录并能联网的板端固件；
- 与数据库一致的节点 ID/注册信息；
- 后端 MQTT 配置；
- 板端与 Broker 之间的网络/账号/ACL。

## 后端 MQTT 配置

默认关闭：

```text
SMARTBOX_MQTT_ENABLED=false
```

启用真实接入时至少需要：

```text
SMARTBOX_MQTT_ENABLED=true
SMARTBOX_MQTT_PROFILE=local|cloud
SMARTBOX_MQTT_URL=tcp://127.0.0.1:1883 或 ssl://<域名>:8883
SMARTBOX_MQTT_USER=smartbox_backend
SMARTBOX_MQTT_PASSWORD=<本地密码>
SMARTBOX_MQTT_CA_FILE=<cloud TLS CA，local 不需要>
```

约束：

- `local` 只接受 `tcp://127.0.0.1:1883`；Broker 若同时监听 LAN，需自行保证板端能访问 Broker 的 LAN 地址。
- `cloud` 只接受 `ssl://`、DNS 域名和 8883 端口，并要求 CA 文件。
- 后端不提供 Broker、账号创建、ACL 或证书轮换。

## 当前 main 的能力边界

main 只保留后端 MQTT 客户端代码，**不提供**：

- EMQX/Mosquitto 部署配置；
- SDK、交叉编译、烧录工具；
- 模拟器；
- 硬件联调脚本；
- 真实板验收。

`firmware/` 仅作为源码参考。需要完整硬件工具时使用完整开发树 `SmartBox-full`，而不是 main。

## 最小判断方法

启动后端后：

- `SMARTBOX_MQTT_ENABLED=false`：只能看到 `DemoFleetService` 的模拟数据；
- `SMARTBOX_MQTT_ENABLED=true` 且 Broker 可达：后端尝试连接 Broker，但开发板仍需单独上电、联网、注册；
- Broker 不可达/账号错误：后端不会自动发现板子，设备数据不会出现。

前端启动成功、页面能打开，不代表开发板已连接。
