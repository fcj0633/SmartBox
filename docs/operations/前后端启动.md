# SmartBox 前后端启动（本地开箱即用）

本仓库按项目所有者要求提交了固定本地演示配置。默认流程不需要手工填写数据库密码、JWT 或 MQTT 环境变量。

> 公开仓库中的数据库/MQTT 凭据对所有访问者可见，只适合演示环境。生产环境必须更换全部凭据。

## 1. 前置条件

- JDK 21
- Maven 3.9+
- MySQL 8（建议 8.4）
- Node.js 22+ / npm
- Windows PowerShell

## 2. 初始化 MySQL

在仓库根目录执行：

```powershell
Get-Content deploy/demo/mysql-init.sql -Raw | mysql -u root -p
```

脚本创建：

- 空库 `smartbox_dev`；
- 运行账号 `smartbox_app`；
- 迁移账号 `smartbox_migrator`；
- 固定演示密码和授权。

### MySQL 8.4 caching_sha2

MySQL 8.4 默认认证插件是 `caching_sha2_password`。本项目固定 JDBC URL 已包含：

```text
allowPublicKeyRetrieval=true&useSSL=false
```

如果仍出现 `Public Key Retrieval is not allowed`，检查：

1. 使用的是仓库中的 `application-dev.yml`；
2. URL 没有被自建环境变量覆盖；
3. MySQL 账号主机与连接主机一致（脚本使用 `127.0.0.1`）。

## 3. LocalSettings 约束

`backend/src/main/java/cn/smartbox/config/LocalSettings.java` 会校验：

- 只能激活 `dev` 或 `test` 一个 profile；
- dev 数据库必须是 `smartbox_dev`；
- `SMARTBOX_DB_URL` 必须是：
  `jdbc:mysql://127.0.0.1:<port>/smartbox_dev...`
- `SMARTBOX_MIGRATION_URL` 必须与数据库 URL 完全一致；
- 应用账号必须是 `smartbox_app`；
- 迁移账号必须是 `smartbox_migrator`；
- JWT 必须是至少 32 字节随机值的 Base64；
- Origin 默认只允许 `http://localhost:5173` 和 `http://127.0.0.1:5173`。

当前默认配置：

```text
backend/src/main/resources/application-dev.yml
```

其中包含固定的本地数据库密码和 JWT；`application.yml` 默认激活 dev：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}
```

## 4. 首次初始化

在仓库根目录执行，且初始化阶段关闭 MQTT：

```powershell
mvn -B -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--smartbox.bootstrap=true --smartbox.assets.bootstrap=true --SMARTBOX_MQTT_ENABLED=false"
```

执行内容：

- Flyway 执行 `V1__current_schema.sql`；
- 创建 `admin/admin` 演示账号；
- 创建 `BOX-0001` 真实箱体身份及 ENV/POSE 节点；
- 加载 5 个模拟箱体、历史任务和告警示例；
- 完成后退出，不常驻 8080。

## 5. 启动后端

```powershell
mvn -B -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--server.port=8080 --smartbox.demo.fleet=true"
```

默认行为：

- 读取 `deploy/demo/mqtt.cloud.json`；
- 固定远程 Broker：`ssl://z789ffe0.ala.cn-hangzhou.emqxsl.cn:8883`；
- 自动使用远程 TLS、固定后端账号和 CA；
- 只订阅 REAL 节点；
- 启动后自动尝试连接。

默认不再需要设置：

```text
SMARTBOX_DB_*
SMARTBOX_JWT_SECRET_BASE64
SMARTBOX_MQTT_*
```

只有在需要覆盖默认值时才设置环境变量。

检查：

```powershell
Invoke-WebRequest http://127.0.0.1:8080/actuator/health
```

- MQTT 已连接：health 200；
- MQTT 已启用但未连接：health 503，日志分类为 DNS/TLS/NETWORK/AUTH；
- 显式关闭 MQTT：health 200，日志提示 disabled。

## 6. 启动前端

另开 PowerShell：

```powershell
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:5173，本地演示账号 `admin/admin`。

Vite 默认代理：

```text
/api -> http://127.0.0.1:8080
/ws  -> ws://127.0.0.1:8080
```

需要改后端地址时：

```powershell
$env:SMARTBOX_API_TARGET = "http://127.0.0.1:8080"
npm run dev
```

## 7. 验证

```powershell
mvn -B -f backend/pom.xml -DskipTests package
npm --prefix frontend ci
npm --prefix frontend run build
```

登录后应看到：

- 总览 6 个箱体；
- `BOX-0001` 为 REAL；BLE/MQTT 配置有效时在线；
- `BOX-SIM-01`～`BOX-SIM-05` 为 SIMULATED；
- 地图与轨迹为 MOCK。

## 8. 故障排查

| 现象 | 原因/处理 |
|---|---|
| `Select exactly one dev/test profile` | 同时激活了 dev/test；保持默认 dev 或只设置一个 |
| `Project database mismatch` | 数据库不是 `smartbox_dev`，或两个 JDBC URL 不一致 |
| `Project database account mismatch` | 应用/迁移账号被改；必须是 `smartbox_app` / `smartbox_migrator` |
| `Public Key Retrieval is not allowed` | JDBC URL 缺少 `allowPublicKeyRetrieval=true` |
| MySQL 认证失败 | 初始化 SQL 未执行，或 MySQL 将 `127.0.0.1` 解析为 `localhost` |
| `JWT key is too short` | 覆盖了固定 JWT；恢复 `application-dev.yml` 中的值 |
| Flyway 校验失败 | 使用了旧 V1–V17 库；使用空库或先备份重建 |
| 8080 被占用 | 停止旧后端或改用 `SERVER_PORT`；前端代理同步修改 |
| 前端能开但 API 失败 | 后端未启动、端口不是 8080、代理目标不对 |
| `npm ci` EPERM | 先停止正在运行的 Vite 进程，再重新 `npm ci` |
| health 503 / mqtt not_connected | 远程 Broker 不可达、CA/账号错误或开发板未连接；查看后端 MQTT 分类日志 |
| `BOX-0001` 离线但板子 Wi-Fi 已连 | Wi-Fi 联网不等于 MQTT 在线；检查节点 ID、Topic、ACL、SNTP、client ID |
| 控制一直待确认 | HTTP 受理不等于设备执行；需要真实设备 ACK |

## 9. 安全边界

- 默认提交的密码/JWT/MQTT 配置仅用于公开演示；
- 不要把该仓库部署到生产网络；
- 更换密码后同步修改初始化 SQL、`application-dev.yml` 和 MQTT 配置。
