# SmartBox 前后端启动（本地演示）

本说明按当前精简仓源码编写。只依赖 Java 21、Maven、MySQL 8、Node.js 22+、npm；默认**无需 MQTT Broker 或实物开发板**。

> 重要：后端 [`LocalSettings.java`](../../backend/src/main/java/cn/smartbox/config/LocalSettings.java) 对开发库、两个 MySQL 用户及 JWT 密钥有严格校验。不能随意改数据库名为 `smartbox`，也不能让应用账号兼用迁移账号。

## 1. 准备本地 MySQL

在 MySQL 管理员连接下执行（仅用于空库/新部署，不覆盖已有库）：

```sql
CREATE DATABASE smartbox_dev
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'smartbox_app'@'127.0.0.1' IDENTIFIED BY 'CHANGE_APP_PASSWORD';
CREATE USER 'smartbox_migrator'@'127.0.0.1' IDENTIFIED BY 'CHANGE_MIGRATION_PASSWORD';

GRANT SELECT, INSERT, UPDATE, DELETE ON smartbox_dev.*
  TO 'smartbox_app'@'127.0.0.1';
GRANT ALL PRIVILEGES ON smartbox_dev.*
  TO 'smartbox_migrator'@'127.0.0.1';
```

注意将两组密码替换为你设置的本地密码。若 MySQL 因主机名解析将 TCP 客户端匹配为 `localhost`，需要为对应主机名配置等效授权；不要放开为所有远程主机。

当前仓库仅保留一个 Flyway 基线：`backend/src/main/resources/db/migration/V1__current_schema.sql`。它面向**全新空数据库**；不能直接对历史 V1～V17 库执行。旧库先备份、核实迁移与历史保留需求，再在独立的新库中重新初始化。

## 2. 设置后端环境变量

在 PowerShell **终端 A，仓库根目录**：

```powershell
$env:SPRING_PROFILES_ACTIVE = "dev"

$env:SMARTBOX_DB_URL = "jdbc:mysql://127.0.0.1:3306/smartbox_dev?connectionTimeZone=UTC&characterEncoding=UTF-8"
$env:SMARTBOX_MIGRATION_URL = $env:SMARTBOX_DB_URL

$env:SMARTBOX_DB_USER = "smartbox_app"
$env:SMARTBOX_DB_PASSWORD = "CHANGE_APP_PASSWORD"
$env:SMARTBOX_MIGRATION_USER = "smartbox_migrator"
$env:SMARTBOX_MIGRATION_PASSWORD = "CHANGE_MIGRATION_PASSWORD"

# 当前会话生成至少 32 字节随机 JWT key
$keyBytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($keyBytes)
$rng.Dispose()
$env:SMARTBOX_JWT_SECRET_BASE64 = [Convert]::ToBase64String($keyBytes)

$env:SMARTBOX_MQTT_ENABLED = "false"
$env:SMARTBOX_BOOTSTRAP_FILE = (Resolve-Path "deploy/demo/bootstrap.example.json").Path
$env:SMARTBOX_ASSET_SEED_FILE = (Resolve-Path "deploy/demo/enterprise-v2.seed.example.json").Path
```

建议在本地安全位置保管 JWT 密钥，避免每次启动都改变导致已签发 Token 失效；**绝不可上传密钥和数据库密码**。`deploy/backend.env.example` 仅为变量清单，Spring Boot/PowerShell 不会自动读取它。

## 3. 第一次运行：建表并初始化演示数据

```powershell
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--smartbox.bootstrap=true --smartbox.assets.bootstrap=true"
```

- Flyway 在新数据库执行 `V1__current_schema.sql`。
- 读取 `deploy/demo/bootstrap.example.json` 创建 `admin/admin` 演示管理员、`BOX-0001` 身份与节点；密码哈希入库。
- 读取 `deploy/demo/enterprise-v2.seed.example.json` 创建演示企业、5 个模拟箱体与历史任务/告警样例。
- 该命令以**非 Web 模式**执行后退出；无需等待它提供 HTTP 端口。
- 重复初始化前必须确认现有数据与种子一致。不能用它覆盖旧库或重置其他人的账号。

## 4. 启动后端 Web 服务

沿用上述 PowerShell 会话：

```powershell
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--server.port=8080 --smartbox.demo.fleet=true"
```

此时由 `DemoFleetService` 每 5 秒左右生成受控模拟遥测。服务端默认仅监听 `127.0.0.1:8080`。检查：

```powershell
Invoke-WebRequest http://127.0.0.1:8080/actuator/health
```

若查看页面的模拟箱体没有新数据，核对是否已完成初始化、模拟资产是否启用、`smartbox.demo.fleet=true` 是否传给了**Web** 启动命令。

## 5. 启动前端

**PowerShell 终端 B**：

```powershell
cd frontend
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173**，本地演示账号为 `admin/admin`。Vue 通过 Vite 的 `/api` 代理调用本机 `8080` 后端。默认后端地址已经写在 `frontend/vite.config.ts`；如果后端端口不同，在启动 Vite 前设置 `SMARTBOX_API_TARGET`。

构建检查：

```powershell
mvn -f backend/pom.xml -DskipTests package
npm --prefix frontend run build
```

注意：以上两条构建命令应在仓库根目录运行；`cd frontend` 之后需要先返回根目录。

## 6. 演示操作路径

1. 登录 `/enterprise` 查看企业总览、真实/模拟资产与运输统计。
2. 选择 `BOX-SIM-01`，查看环境采样；切换模拟场景观察高温、离线或冲击事件。
3. 创建运输 READY，选择在线模拟箱体和预设路线；开始变为 ACTIVE，模拟位置按服务端时间推进。
4. 在地图与详情页查看任务、位置和事件；结束运输后查看 COMPLETED 和历史。
5. 控制页面可演示命令受理和操作状态，但 `SMARTBOX_MQTT_ENABLED=false` 时无法获得真实设备 ACK。

## 7. 需要连接真实开发板时

浏览器无法直连开发板：`ENV/POSE → Wi-Fi → 远程 MQTT Broker（TLS 8883）→ Spring Boot → MySQL → Vue`。

后端必须设置：

```text
SMARTBOX_MQTT_ENABLED=true
SMARTBOX_MQTT_URL=ssl://<受控 DNS Broker 主机>:8883
SMARTBOX_MQTT_USER=smartbox_backend
SMARTBOX_MQTT_PASSWORD=<本地机密>
SMARTBOX_MQTT_CA_FILE=<CA PEM 绝对路径>
```

后端仅支持远程 TLS DNS Broker `8883`，不提供本地 `1883` 回退；还需在 Broker 侧准备正确节点身份、ACL、证书信任链和可上报的实板固件。

本精简仓**没有** SDK、烧录、Broker 管理与真实硬件联调工具。详情见 [真实开发板接入](真实开发板接入.md)；不要将该流程视为已在本次本地演示中验证。

## 8. 常见问题

| 现象 | 常见原因与处理 |
|---|---|
| `Project database mismatch` | `SMARTBOX_DB_URL` 应为 `127.0.0.1` 上的 `smartbox_dev`，与 `SMARTBOX_MIGRATION_URL` 完全一致 |
| `Project database account mismatch` | 开发 Profile 下应用用户必须是 `smartbox_app`，Flyway 用户必须是 `smartbox_migrator` |
| `Select exactly one dev/test profile` | 需要设置 `SPRING_PROFILES_ACTIVE=dev`，且不要同时激活 `test` |
| `Missing database credential` 或认证失败 | 检查数据库用户、主机授权、密码和两个连接变量 |
| `JWT key is too short` | 需要至少 32 字节随机密钥编码为 Base64 |
| Flyway 校验/版本冲突 | 误用了旧 V1～V17 库；备份后在**新库**初始化，不能靠修改旧迁移绕过 |
| 前端能开但 API 失败 | 确认后端 `8080` 正在运行，Vite 代理地址正确 |
| 只看到模拟箱体或无实物读数 | `BOX-0001` 的数据库身份不代表真实板已接入；需要单独完成 MQTT/TLS/固件配置 |
| 设备控制长时间待确认/超时 | 纯模拟数据库模式没有实物设备 ACK；HTTP 受理不是设备执行成功 |
| 生产静态页面刷新 404 | Vite 代理只适用于开发服务；公网部署需自行配置静态页面 History 回退和 `/api` 反向代理 |

## 9. 安全和部署边界

`admin/admin` 仅用于隔离的本地演示。公网/共享部署前需要更换演示密码、数据库密码、JWT 密钥，并另外完成 HTTPS、域名、反向代理和网络访问控制。

当前后端默认绑定本地 `127.0.0.1`，本仓库**不是开箱即用的生产部署包**；没有自动化测试、Docker Compose、真实设备烧录或长期可靠性验证，不应把构建/启动成功描述成生产可用。
