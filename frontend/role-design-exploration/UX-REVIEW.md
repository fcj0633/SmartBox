# 骑手端与普通用户端 UI/UX 评审及改版记录

日期：2026-11-23。执行者：Codex；用户独立评审与验收。改版基于 `8939671` 工作区与用户本次完整优化任务，范围仅独立原型。规范来源为[多角色需求说明](../../docs/history/SmartBox多角色物流箱管理平台需求变更说明.md)，设计系统与启动方式见 [README](README.md)。不修改企业方向稿、生产网页、后端、数据库、正式权限或协议。

## 1. 现状审查与证据

修改前，使用项目已安装 Playwright 启动真实 Chromium，重新捕获四种原版式在 390×844、768×1024、1440×900 的首页，共 12 张。保存在本机 `artifacts/role-ux-optimization/before/`，并实际打开主要截图检查。本次证据不是沿用旧缓存或生成的概念图。

| 步骤 | 审查表面及健康情况 | 实际依据 | 影响与处理 |
|---|---|---|---|
| 1 | 骑手 A 首页：资产入口齐全，但当前运输优先级不足 | `before/rider-a-mobile.png`、`before/rider-a-desktop.png`；原 App 资产首页模板 | 来源标签、双插画和两张资产卡抢占空间，当前任务只在下方摘要；改为当前运输主区，来源放入箱体列表 |
| 2 | 骑手 B 首页：任务入口清楚，但环境结论迟到 | `before/rider-b-mobile.png`；原移动环境面板位于 work-next 后 | 手机首屏先出现“接下来”和新运输准备，环境摘要在下方；将环境并入当前任务，把新运输入口降为次要 |
| 3 | 用户 A 首页：阶段明确，但需要先读完整时间线 | `before/customer-a-mobile.png`；原 customer-journey 模板 | 物品、品牌文案、时间线之后才出现环境；改为任务身份与环境先行，进度放在后面 |
| 4 | 用户 B 首页：环境突出，但运输身份弱、曲线过早 | `before/customer-b-mobile.png`、`before/customer-b-desktop.png`；原 monitor 模板 | 首页完整曲线、折叠运输区与侧栏重复任务；合并为任务概览，删除访客模块导航，将曲线下沉 |
| 5 | 新运输关联：存在业务状态风险 | 原 App 的 prepare()/bind() 固定 `SBX-24021` / `DEMO-1123-021`；源版本可由 `74d7dc0` 查阅 | 从另一箱体发起时可能写入固定任务；拆出 usePreview，以箱体查找准备任务，无准备任务则建立独立 Demo 任务，开始时重验占用 |
| 6 | 访客直达：原型查看门槛可绕过 | 原 App entered 初始化及 chooseReviewPage() 对非入口页自动置 true | 原来是评审便利，但不符合本次验证要求；现在 URL 和评审工具不建立查看资格，刷新、退出和失效停止展示，始终经模拟校验进入 |

第 1–4 项为浏览器首页证据，第 5–6 项为代码审查发现，未把修改前未捕获的完整操作流程宣称为浏览器实测。原四版保留的优点：两种箱体来源、统一数据质量意识、任务历史与当前读数分离、无虚构真实位置/信号、模拟说明与只读告警边界。

视觉及可读性风险：原 CSS 在来源、时间、状态与曲线说明中多次使用 9–10px 字号；首页大量相同容器、状态标签与品牌文案让主次接近。改版将辅助字调整至通常 12–13px，状态正文 14–16px，统一颜色与排版，减少重复说明。截图不能证明读屏完整可用或符合全部 WCAG 要求；本轮仅验证与页面相关的标签、焦点及基本键盘行为。

## 2. 重组后的信息架构与视觉判断

骑手以工作台为首页：进行中任务的物品、箱体、开始时间、环境结论、读数、最近更新时间和“查看当前运输”形成一个主要区块；异常摘要位于读数前。无运输时替换为可操作的开始入口，不保留空任务票据。不同箱体可演示多任务，各自进入对应任务。我的箱体与记录使用平面列表；设备节点和权限是二级详情。

访客以已验证任务为上下文：先显示物品与任务编号、运输中/已结束，再显示环境结论与读数，环境历史和异常只有一个明确入口。运输进度在移动端位于环境之后，桌面与环境并列。无顶部/底部模块导航，无管理、结束或控制按钮。

视觉方案采用给定深蓝/青绿品牌，不另造主题：白色仅承载主要任务/环境，次级列表用留白与细线；正常状态没有大面积彩色徽章。琥珀用于品牌与焦点，红色只用于异常及危险动作。删除业务页面的大型插画、宣传式标题和完整曲线。原 BoxArt 文件保留，业务入口不再反复使用。

首页人工检查结论：骑手手机视口能在首屏看到环境结论、读数与主要任务按钮；用户手机视口同时呈现任务状态和环境结论。768px 使用任务主区和箱体/进度侧区，不只是放大手机；1440px 内容上限 1160px、非对称双栏，避免为了填满屏幕增加数据。底部导航仅骑手使用，末尾预留空间。四种原版式不再作为现版可切换设计，历史版本留 Git。

## 3. 实现与交互修复

- App 外框拆出 RiderHome、TransportOverview、PrepareFlow；独立 usePreview 管理演示数据与动作，Environment 只展示摘要，Trend 仅用于历史。组件职责、色彩、字级、间距、按钮与响应式细则在 README 中有统一规范。
- 选箱后选择该箱体的准备任务，绑定只更新目标任务。个人箱体结束后可建立独立新任务，不覆盖同箱旧任务。任务选择同步箱体，箱体当前快照与任务历史分开。
- 开始前核对物品、使用资格和占用，重复结束不再出现可执行按钮。企业分配失效只限制分配箱，离线开始采用有明确原因的演示限制；正式条件仍待确认。
- 完成任务冻结当时读数、样本时间和质量。当前异常场景不把前次任务的 5.1°C 改为 8.6°C 或当前 4.8°C。完成后“末次记录正常”不承诺全程正常。
- 访客验证不写 URL 凭据、不使用生产 Token；参数直达、页面选择器、退出后返回均不能自动展示任务，失效后重新验证。
- 替换原硬编码装饰路径和统一填充面积为可查阅的模拟采样数组；断点不连接，无效/离线/过期有缺口。起止同一演示时刻时不绘制假时序。
- 确认弹窗使用初始焦点、Tab 循环、Escape 关闭与焦点返回。导航完成后在 DOM 更新后滚动至顶部，避免从表单进入概览时顶部被裁掉。无效采样明确显示“本次采样”，避免误称最近有效采样。
