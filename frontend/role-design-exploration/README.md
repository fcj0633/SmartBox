# SmartBox 骑手与普通用户交互原型

依据[多角色需求变更说明](../../docs/requirements/SmartBox多角色物流箱管理平台需求变更说明.md)实现的独立 Vue 原型。本次将原四套探索稿收敛为骑手个人运输工作台、普通用户运输观测页，允许大幅调整布局的依据为用户本次 UI/UX 优化任务。此前 A/B 源码仍可从 Git 提交 `74d7dc0` 查阅；现有 `layout=a/b` 参数不再切换版式。

[生产前端](../README.md)与[企业端方向稿](../design-exploration/README.md)保持独立。这里的数据、身份和动作均为 Demo / Mock，真实服务为 Planned，不连接 API、数据库、设备命令或真实登录 Token。本原型不能证明服务端鉴权、并发和硬件能力已经实现。

## 2. 页面结构与核心路径

骑手一级导航：工作台、我的箱体、运输记录、我的。工作台先展示进行中运输与环境摘要；无运输时突出开始入口，多任务用简洁列表。资产来源、占用及节点在线状态放在简洁箱体行中。异常在任务内查看，不设置虚假的处理、确认或关闭操作。

```text
工作台 → 当前运输 → 环境记录 / 异常记录 / 结束确认
工作台 / 我的箱体 → 开始新运输 → 选箱 → 绑定物品 → 核对 → 开始确认
运输记录 → 对应任务 → 该任务环境 / 异常
我的 → 使用关系与权限说明 / 退出演示
```

普通用户不提供顶部或底部模块导航：

```text
运输编号＋验证码 → 运输概览（物品、运输状态、环境结论、读数）
                   ├→ 查看环境记录 → 返回运输概览
                   └→ 异常记录 → 只读异常详情
访问失效 → 停止展示 → 重新验证
```

首页没有完整曲线和大型箱体插画。设备节点、质量四维解释和权限通过详情与可展开说明渐进展示。运输概览融合运输身份与环境，不再把运输与环境拆成彼此独立的两种首页。

## 3. 设计规范

| 项目 | 规范 |
|---|---|
| 品牌与正文 | 深蓝 `#183746`；正文 `#203D46`；背景 `#F7F9F6`；分隔 `#DCE5E2` |
| 操作与状态 | 青绿 `#147B67` 用于主操作与有文字说明的正常状态；琥珀 `#E9A354` 用于品牌点缀与键盘焦点；不确定用 `#926324`；异常/危险文字 `#B84135`；灰色表示不可用 |
| 字体 | Segoe UI、微软雅黑、系统中文回退，不加载远程字体；标题 24–30px，区域 18–22px，正文 14–16px，辅助通常 12–13px，读数 40–52px |
| 间距 | 4/8/12/16/24/32px 为基础，桌面主要分栏 32–48px；手机横向留白 20px |
| 容器 | 主任务/环境面板有白底、细边框、10–12px 圆角；箱体、记录和辅助入口用分隔线，不嵌套相同卡片，不加常规阴影 |
| 按钮 | 主按钮青绿，次要白底描边，结束使用危险色；主操作至少 48px 高；每页以当前任务为主，多个运输时每条对应自己的入口 |
| 状态 | 文字、图标和颜色共同表达；异常有事件摘要，离线/过期有最后有效时间和旧值说明，无效显示破折号，未知不推导成正常 |
| 响应式 | ≤700px 单列，骑手底部四入口并预留底部空间，访客无底栏；768px 采用不同宽度的任务与箱体/进度分栏；桌面内容上限 1160px，环境与进度非对称分栏 |
| 可访问性 | 原生表单标签、可见键盘焦点、状态文字；确认弹窗初始焦点、Tab 循环、Escape 关闭和关闭后焦点返回；不据截图宣称完整无障碍认证 |

详细评审、证据及实现调整见 [UI/UX 评审与改版记录](UX-REVIEW.md)。

## 5. 需求映射及演示规则

| 页面/流程 | 来源 | 原型行为 | 正式接入边界 |
|---|---|---|---|
| 工作台/箱体/我的 | MR-RID-001/003/007，MR-COM-001/002/004 | 两种来源、节点在线、占用、权限独立说明 | 企业/个人权属与分配仍待后端设计 |
| 选箱/绑定/开始 | MR-RID-002/004，MR-COM-003/006/007 | 目标箱体准备任务，空名称校验，占用/失效拒绝，核对确认 | 任务签发、物品最低条件、真实排他/幂等待确认与实现 |
| 结束/复用/历史 | MR-RID-005/006，MR-COM-005/007 | 结束后冻结任务读数和质量；同箱新任务独立 | 服务端时间归属、并发、补传、撤权后历史边界未实现 |
| 普通用户验证/失效 | MR-CUS-001/005，MR-COM-002 | 校验模拟编号与验证码，拒绝参数直达、失效不显示数据 | 凭据签发、有效期、限流和服务端资源授权为 Planned |
| 运输概览/曲线/异常 | MR-CUS-002/003/004，MR-COM-004/005 | 仅选中任务，旧任务 5.1°C 与当前 4.8°C 隔离，只读异常 | 三端使用服务端统一投影，不增加独立阈值引擎 |

- 示例日期 `2026-11-23`，静态更新时间 `14:32`。个人箱 `SBX-24018`：前次任务 `DEMO-1123-006` 09:12–10:40，5.1°C；当前 `DEMO-1123-018` 13:10 开始，4.8°C。企业分配箱 `SBX-24021`：准备任务 `DEMO-1123-021`，6.2°C。任务新建编号为显式 `DEMO-1123-N…`，不代表正式签发规则。
- 单箱单进行中为 V1 暂定；演示多任务是不同箱体各自进行运输，不增加同箱并行能力，不替 MR-Q-12 做决定。
- 单个名称/简述、离线时暂不允许演示开始、异常可确认结束仅用于原型流程；真实开始/结束及离线策略、物品数量、接管资格仍待确认，不提升为正式规则。
- 已结束任务不再跟随当前箱体场景变化，末次正常不推断全程安全；结束不代表签收、异常恢复或数据已补齐。离线/过期保留最后有效时间，无效隐藏数值。历史图使用可展开的六个等间隔模拟样本，缺失断开；开始结束同一演示时刻时不绘制虚假曲线。
- 无箱体、无运输、多个运输、异常、离线、无效、过期、未知、分配失效、验证码失败与授权失效均有演示场景。分配失效只约束企业箱，不撤销个人所有权。
- 不新增地图、位置、ETA、签收、设备电量/信号、复杂物品字段、取消/重开/运输中换箱、设备控制或人工告警处置。
