# SmartBox 骑手端与普通用户端版式预览

依据[多角色需求变更说明](../../docs/requirements/SmartBox多角色物流箱管理平台需求变更说明.md)，为两个用户端各提供两套可点击高保真版式。两端可独立选择 A/B，不需要成套选择。

这是独立 Vue 预览，保留[生产前端](../README.md)和[企业端方向稿](../design-exploration/README.md)。所有数据与操作均为 Demo / Mock，未接入正式认证、API、数据库、消息通道或设备命令，不证明后端资源隔离已实现。

## 1. 启动和查看

复用已安装的锁定依赖，无新增依赖。从仓库根目录启动：

```powershell
frontend/node_modules/.bin/vite --config frontend/role-design-exploration/vite.config.ts
```

打开 `http://127.0.0.1:5187`。评审工具可以选择用户端、版式、页面、场景，并重置演示。可用 URL 直接打开：

| 版式 | 含评审工具的地址 |
|---|---|
| 骑手 A：我的箱体 | `http://127.0.0.1:5187/?role=rider&layout=a&page=home` |
| 骑手 B：运输工作台 | `http://127.0.0.1:5187/?role=rider&layout=b&page=home` |
| 用户 A：运输时间线 | `http://127.0.0.1:5187/?role=customer&layout=a&page=entry` |
| 用户 B：环境监测页 | `http://127.0.0.1:5187/?role=customer&layout=b&page=entry` |

追加 `&presentation=1` 可隐藏评审工具查看产品画面；去掉该参数即可恢复工具。`page=home` 等直达地址是评审工具建立的演示上下文，不是访客鉴权方案。正常用户流程从 `page=entry` 输入两项演示信息开始。

公开演示运输编号：`DEMO-1123-018`（进行中）、`DEMO-1123-006`（已结束）。演示验证码：`DEMO-4821`。它们是公开的模拟值，不是现网凭据。任意错误输入都不建立任务查看状态，访问失效场景停止展示任务内容。

## 2. 版式与设计系统

| 版式 | 首要任务 | 页面组织与差异 |
|---|---|---|
| 骑手 A | 找到自己的箱体，核对来源与状态 | 箱体卡片列表、选中资产环境摘要；底部箱体/运输/异常/我的导航；桌面列表与详情双栏 |
| 骑手 B | 处理正在执行的运输及下一步 | 深蓝运输票据、阶段记录、琥珀操作入口；当前任务主区与箱体侧栏；选箱/物品/开始分步完成 |
| 用户 A | 了解本次运输进展和已记录事实 | 物品摘要、运输时间线为主；环境摘要与历史为辅助；桌面时间线与监测双栏 |
| 用户 B | 快速理解本次环境与变化 | 环境结论、大读数、任务范围曲线为主；运输摘要可展开；环境/运输/异常页内导航 |

品牌色参考已选企业地图方向：深蓝 `#183746`、青绿 `#147b67`、琥珀 `#e9a354`、背景 `#f7f9f6`、正文 `#203d46`、浅分隔 `#dfe8e3`。物品插画为项目原生 SVG，不调用图像或地图服务。字体使用本机 Segoe UI、微软雅黑及系统中文回退，无远程字体加载。

主要正文/表单为 14–16px，标题 20–29px；时间、来源、演示标记等辅助信息较小。选项间保留相同品牌而改变信息优先级，避免把两个端做成企业后台的缩小版。图表按任务呈现，有效性、新鲜度与环境结论独立显示，颜色之外保留文字标签。

## 3. 页面与需求映射

下表中的 MR 标识来自同一需求变更说明，非新正式 REQ。两种版式覆盖同样页面，不因版式取舍业务。

| 页面/流程 | 需求映射 | 本原型行为 | 真实接入边界 |
|---|---|---|---|
| 骑手入口、我的箱体 | MR-RID-001/007，MR-COM-001/002 | 示例身份进入，两种权属来源标签与状态；选择箱体 | 复用现有登录基础，新增权属与使用授权尚待设计 |
| 箱体详情、节点/环境 | MR-RID-003/007，MR-COM-004 | ENV/POSE、未知门状态、有效/过期/无效/离线；不编造电量或信号 | 数据取统一服务端投影；本原型不提交设备命令 |
| 选箱、绑定、开始、结束 | MR-RID-002/004/005，MR-COM-003/006/007 | 已占用箱体不能开始另一任务，物品绑定与确认弹窗，单次开始/结束与记录 | 只更新内存；字段/数量/操作资格等未决条件不是正式规则 |
| 运输记录、任务历史 | MR-RID-006，MR-COM-005 | 原箱体先后两任务，各自独立读数和时段；结束不覆盖旧任务 | 真实时间归属、补传、并发及幂等由后端实现 |
| 编号＋验证码、失效 | MR-CUS-001/005，MR-COM-002 | 模拟验证、失败提示、结束任务验证及失效页面；无完整账号注册 | 凭据签发/存储/时长/限流/撤销机制仍 Planned |
| 用户概览、环境和异常 | MR-CUS-002/003/004，MR-COM-004/005 | 两种布局、只读任务页、历史曲线、异常详情弹窗 | 访客没有箱体管理、节点诊断、配置、导出或命令入口 |

## 4. 数据、状态与未决规则

- 示例日期锚定客户端本次任务日期 **2026-11-23**；14:32 是静态演示更新时间，不宣称实时联网。资产归属、身份、物品和数据均为公开虚构例子，不包含联系方式。
- 个人箱体 `SBX-24018` 的已结束任务 `DEMO-1123-006` 为 09:12–10:40、5.1°C；后续任务 `DEMO-1123-018` 为 13:10 开始、4.8°C。两者的数据和查看上下文独立。
- 企业分配箱体 `SBX-24021` 有准备中任务 `DEMO-1123-021`。选箱、绑定、开始、结束在当前内存会话中执行；刷新或点击重置恢复初始数据，不使用持久登录 Token。
- 正常场景的 2–8°C 与 45–70% 只为演示画像，不写入需求或设备；异常场景展示同一模拟结果 8.6°C，不在前端判断正式阈值。
- 场景工具支持环境异常、节点离线、采样无效、过期、判断未知、无可用箱体、分配失效、验证失败和访问失效；离线/无效的曲线保留缺口。
- 图表时段选项目前标明 Planned，切换不会伪造筛选结果。不能把没有异常记录解释成数据无效时“环境正常”。
- 分配失效约束企业分配箱体的演示操作，不因它撤销个人箱体所有权；运输中真实接管规则仍待确认。
- 开始/结束前有确认；结束后保留记录并不表示签收、告警恢复或断网数据已完整补传。演示要求填写一个名称仅用于交互展示，不确立“一任务一物品”规则。
- 不实现取消、重开、换箱、画像/校准扩权、灯风扇命令、人工告警关闭、路线优化或 ETA。真实软件的身份、时间、控制与状态语义仍以现行基线为准。

## 5. 检查与截图

类型检查与独立构建（仓库根目录）：

```powershell
frontend/node_modules/.bin/vue-tsc --noEmit --project frontend/role-design-exploration/tsconfig.json
frontend/node_modules/.bin/vite build --config frontend/role-design-exploration/vite.config.ts --outDir ../../artifacts/role-design-exploration/build
```

启动本预览后，在另一终端使用匹配的本机浏览器缓存执行[独立验证脚本](tests/verify.cjs)：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = (Resolve-Path artifacts/task006/browsers).Path
node frontend/role-design-exploration/tests/verify.cjs
```

该脚本遍历四版的关键页面与 390×844、768×1024、1440×900 三种尺寸；验证绑定/开始/结束、占用约束、查询失败/成功、前后任务读数独立、状态场景、告警只读弹窗、版式切换及无真实 API/外网请求。它验证的是原型行为，不证明真实鉴权、后端并发、设备通信或业务验收。

输出位于忽略的本机目录 `artifacts/role-design-exploration/`：

- `screenshots/`：四版手机/平板/桌面首页与手机关键流程、错误和状态截图。
- `rider-comparison.png`、`customer-comparison.png`：同用户端的 A/B 版式对比图，由浏览器排版未改动的实际视口截图生成。
- `verification.json`：实际遍历数、交互结果和截图清单。

常规检查仍使用 `.venv/Scripts/python tools/frontend.py check` 与 `.venv/Scripts/python tools/check_docs.py`。本轮仅交付四套选择稿，选定骑手版式和用户版式后，再继续完善和接入真实接口。
